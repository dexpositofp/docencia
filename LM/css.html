CSS: del estilo básico al layout profesional

Fundamentos, arquitectura, layout moderno, responsive, rendimiento y accesibilidad

1. Qué es CSS

Objetivos de aprendizaje: al terminar este punto podrás (1) explicar qué problema resuelve CSS, (2) describir cómo decide el navegador los estilos finales (cascada/herencia/especificidad a alto nivel), (3) elegir la forma adecuada de incluir CSS en un proyecto y (4) crear una base tipográfica y de color coherente.

1.1. ¿Qué es y qué NO es CSS?

CSS (Cascading Style Sheets) define la presentación de un documento HTML: tipografía, colores, espaciados, disposición (layout), estados interactivos y animaciones.
CSS no es un lenguaje de programación general: no procesa datos ni maneja lógica de negocio (eso lo hace JavaScript); su foco es el aspecto visual, de forma declarativa.

1.2. Modelo mental del navegador

Para entender por qué a veces los estilos “no se aplican” o el navegador recalcula cosas, es importante conocer a grandes rasgos el pipeline de renderizado.

  1. Construcción del DOM (Document Object Model): el navegador lee el HTML y lo transforma en un árbol de nodos. Cada etiqueta se convierte en un nodo, que puede tener atributos, hijos y texto. Este árbol es accesible desde JavaScript y se actualiza en tiempo real si el contenido cambia. 
    <body>
  <h1>Título</h1>
  <p>Un párrafo con <em>énfasis</em>.</p>
</body>
    DOM resultante:
body
 ├── h1 ("Título")
 └── p
      ├── "Un párrafo con "
      └── em ("énfasis")
  2. Construcción del árbol de estilos (CSSOM): se leen todas las hojas de estilo (externas, internas, en línea) y se combinan en un conjunto de reglas aplicables.
  3. Cálculo de estilos computados: para cada nodo del DOM, el navegador resuelve la cascada, la herencia y la especificidad para decidir qué valores finales tiene cada propiedad.
  4. Layout y pintura: con los estilos ya calculados, el motor determina el tamaño y la posición de cada caja (layout). Luego “pinta” colores, bordes, fondos y texto en la pantalla y finalmente compone capas si hay transparencias, transformaciones o animaciones.

Optimización: no todas las propiedades cuestan lo mismo. Cambiar color o opacity solo repinta; cambiar transform suele ser barato (usa la GPU); pero cambiar width, height o top obliga a recalcular layout, que es más costoso.

1.3. Dónde escribir CSS (y cuándo)

CSS se puede incluir de varias maneras en un documento. Cada método tiene sus ventajas e inconvenientes. En proyectos reales, casi siempre se usa hoja externa, pero conviene conocerlos todos.

  • Hoja externa (recomendado): Se enlaza desde el <head> con <link>. Ventajas: caché del navegador, separación clara entre estructura (HTML) y estilos (CSS), y fácil escalado en proyectos grandes. 
    <!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <title>Ejemplo externo</title>
  <link rel="stylesheet" href="estilos.css">
</head>
<body>
  <h1>Hola, mundo</h1>
</body>
</html>
    /* archivo estilos.css */
h1{ color: steelblue; font-family: sans-serif; }
  • <style> en el <head>: Útil para prototipos rápidos, demos o pruebas locales, aunque menos mantenible. 
    <head>
  <style>
    h1{ color: crimson; }
  </style>
</head>
  • Estilo en línea (style="..."): Aplica estilos directamente en un elemento. Es poco recomendable porque rompe la separación de responsabilidades, sube la especificidad y hace más difícil el mantenimiento. Solo debe usarse en casos muy puntuales (ej. enviar HTML por email). 
    <h1 style="color: green; font-size: 2rem">Título con estilo en línea</h1>

Mala práctica: llenar el HTML de estilos en línea o depender de hojas internas grandes. Lo ideal es centralizar reglas en uno o varios archivos externos y aplicar estilos con clases reutilizables.

1.4. Ejemplo de regla CSS comentada

Una regla CSS se compone de:

  1. Un selector → a qué elementos aplica
  2. Un bloque de declaraciones → entre { }
  3. Cada declaración = propiedad : valor; 

/* Ejemplo: todos los párrafos */
p {
  color: blue;         /* propiedad: color → valor: blue */
  margin-bottom: 1rem; /* propiedad: margin-bottom → valor: 1rem */
}

👉 En este caso, el selector es p, que apunta a todos los párrafos. Dentro de las llaves están las declaraciones, cada una con una propiedad y un valor.

/* Selector de clase (.destacado) → solo a elementos con class="destacado" */
.destacado {
  background-color: yellow;  /* fondo amarillo */
  font-weight: bold;         /* texto en negrita */
}

👉 Si en tu HTML escribes <p class="destacado">...</p>, ese párrafo tendrá fondo amarillo y texto en negrita.

1.6. Errores frecuentes (y cómo evitarlos)

  • Abusar de style= en línea → sube la especificidad y dispersa la lógica visual. Solución: centraliza en clases y componentes.
  • Usar píxeles fijos para todo → mala adaptación. Solución: usa rem, % y clamp().
  • Confundir estructura con estilo → HTML “de maquetación” (tablas/divs vacíos). Solución: HTML semántico + CSS para el layout.
  • Subir la especificidad sin necesidad (#id .clase elemento) → reglas difíciles de mantener. Solución: selectores simples, BEM y, si procede, @layer.
  • No pensar en estados (focus/hover/disabled) → mala UX/AX. Solución: define estados con :hover, :focus-visible, [aria-*].

2. Selectores en CSS

En CSS, un selector es el mecanismo que utilizamos para indicar a qué elementos HTML queremos aplicar estilos. Cuando escribimos una regla CSS, siempre tenemos dos partes: el selector (qué elementos serán afectados) y el bloque de declaraciones (qué estilo se aplicará). 

selector {
  propiedad: valor;
}

Si el navegador no sabe a qué elementos se aplica una regla, esa regla se ignora. Por eso es fundamental dominar los selectores: nos permiten ser precisos y evitar dar estilos de más o de menos.

2.1 Selectores básicos

  • Selector de tipo: selecciona todos los elementos de una etiqueta concreta. 
    p { color: blue; }

    Afecta a todos los párrafos de la página.

  • Selector de clase: selecciona elementos con un atributo class específico. Las clases se definen en el HTML y se reutilizan en varios elementos. 
    <p class="destacado">Texto importante</p>
    .destacado { font-weight: bold; color: red; }
  • Selector de id: selecciona un elemento con un atributo id concreto. El id debe ser único en cada documento HTML. 
    <h1 id="titulo-principal">Bienvenido</h1>
    #titulo-principal { text-align: center; }
  • Selector universal: selecciona todos los elementos. 
    * { font-family: Arial, sans-serif; }

    Es útil para aplicar un estilo global, pero se debe usar con cuidado porque afecta a todo.

Diferencia entre clase e id: - Usa class cuando quieras aplicar el mismo estilo a varios elementos (ejemplo: .boton en varios botones). - Usa id solo cuando quieras identificar un único elemento (ejemplo: #menu-principal).

2.2 Combinadores (selectores en función del contexto)

Muchas veces no basta con seleccionar por tipo, clase o id: necesitamos seleccionar un elemento en función de su posición en el árbol HTML. Para eso usamos los combinadores.

  • Descendiente: selecciona todos los elementos dentro de otro. 
    article p { color: green; }

    Afecta a todos los <p> que estén dentro de un <article>.

  • Hijo directo (>): selecciona solo los elementos que son hijos inmediatos. 
    div > p { background: lightgray; }
  • Hermano adyacente (+): selecciona el primer elemento que sigue inmediatamente a otro. 
    h2 + p { font-style: italic; }
  • Hermanos generales (~): selecciona todos los elementos hermanos que siguen a otro. 
    h2 ~ p { color: orange; }

2.3 Selectores de atributos

Con los selectores de atributos podemos aplicar estilos en función de los valores de los atributos HTML.

  • a[href] → todos los enlaces que tengan atributo href.
  • a[href^="https"] → enlaces cuyo href empiece por “https”.
  • a[href$=".pdf"] → enlaces que terminen en “.pdf”.
  • input[type="text"] → campos de formulario de tipo texto.

2.4 Pseudo-clases (estados y posición)

Las pseudo-clases permiten aplicar estilos según el estado de un elemento o su posición en el DOM.

  • a:hover → cuando el ratón pasa por encima de un enlace.
  • input:focus → cuando un campo de formulario está activo.
  • p:first-child → selecciona el primer hijo de su contenedor.
  • li:nth-child(2) → selecciona el segundo elemento de una lista.

2.5 Pseudoelementos (partes de un elemento)

Los pseudoelementos permiten aplicar estilos a partes específicas de un elemento sin necesidad de añadir etiquetas nuevas.

  • ::before y ::after → insertan contenido generado antes o después del elemento.
  • ::first-line → aplica estilo a la primera línea de un párrafo.
  • ::first-letter → aplica estilo a la primera letra.
  • ::marker → modifica los marcadores de listas (ul, ol).

Ejemplo práctico completo:

<article>
  <h2>Título</h2>
  <p class="destacado">Primer párrafo</p>
  <p>Segundo párrafo</p>
  <ul>
    <li>Elemento 1</li>
    <li>Elemento 2</li>
  </ul>
</article>
article p.destacado { color: red; }
article > p + p { font-style: italic; }
ul li:first-child { font-weight: bold; }
ul li::marker { color: blue; }

2.6 Mini-reto

Crea una lista de enlaces (<a>) y aplica estos estilos:

  • Que los enlaces sean azules normalmente.
  • Que se subrayen de color rojo al pasar el ratón (:hover).
  • Que los que apunten a archivos PDF ([href$=".pdf"]) aparezcan en verde.

3. Propiedades CSS más utilizadas

CSS incluye cientos de propiedades, pero en la práctica hay un conjunto reducido que se utilizan a diario y que conviene dominar. Para aprenderlas de forma más clara, las agrupamos en categorías según el aspecto que controlan: tipografía, color y fondos, modelo de caja (espaciados y tamaños), y bordes/sombras.

3.1. Propiedades de texto y tipografía

Controlan cómo se muestra el texto en la página. Al trabajar con tipografía en CSS, lo más habitual es definir la familia tipográfica, el tamaño, el peso (grosor), el estilo (normal o cursiva), la altura de línea y la alineación. Además, podemos transformar el texto en mayúsculas/minúsculas, decorarlo con subrayados o tachados, y definir el color con la propiedad color.

  • font-family: define la familia tipográfica. Ej: font-family: Arial, sans-serif;
  • font-size: define el tamaño del texto. Ej: font-size: 16px;
  • font-weight: define el grosor (normal, bold o valores entre 100–900). Ej: font-weight: 700;
  • font-style: estilo de la fuente (normal, italic, oblique).
  • line-height: espacio vertical entre líneas. Ej: line-height: 1.6;
  • text-align: alineación horizontal del texto (left, center, right, justify).
  • text-transform: transforma el texto en mayúsculas/minúsculas. Ej: uppercase, capitalize.
  • text-decoration: añade o quita subrayados, tachados. Ej: underline.
  • color: color del texto.
h1 {
  font-family: Georgia, serif;
  font-size: 2rem;
  font-weight: 700;
  text-align: center;
  color: darkblue;
}

3.2. Propiedades de fondo y color

Sirven para definir colores de fondo o imágenes decorativas detrás del contenido. Podemos decidir si una imagen se repite o no, su tamaño y cómo se coloca dentro de la caja del elemento.

  • background-color: color de fondo. Ej: background-color: lightblue;
  • background-image: imagen de fondo. Ej: background-image: url('fondo.png');
  • background-repeat: si la imagen se repite (repeat, no-repeat, repeat-x, repeat-y).
  • background-size: tamaño de la imagen (auto, cover, contain, valores en px/%).
  • background-position: punto de inicio de la imagen (center, top, 50% 50%).
body {
  background-color: #f0f0f0;
  background-image: url("pattern.png");
  background-repeat: repeat;
  background-size: 200px 200px;
}

3.3. Propiedades de caja y espaciado

Cada elemento HTML se representa en pantalla como una caja rectangular. Con estas propiedades controlamos el tamaño de esa caja, los espacios interiores (padding), los espacios exteriores (margin) y cómo se calculan los tamaños en relación con el borde y el relleno (box-sizing).

  • width / height: ancho y alto del contenido.
  • max-width / min-width: límites máximos y mínimos de ancho.
  • margin: espacio exterior (entre la caja y otros elementos). Ej: margin: 1rem auto;
  • padding: espacio interior (entre contenido y borde). Ej: padding: 20px;
  • box-sizing: define cómo se calculan ancho y alto (content-box, border-box).
.card {
  width: 300px;
  padding: 1rem;
  margin: 1.5rem auto;
  box-sizing: border-box;
}

Ejemplo práctico del modelo de caja

.caja {
  width: 200px;              /* ancho del contenido */
  height: 100px;             /* alto del contenido */
  padding: 20px;             /* espacio interior */
  border: 5px solid black;   /* borde */
  margin: 15px;              /* espacio exterior */
  background: lightyellow;   /* fondo */
}
<div class="caja">Contenido</div>

3.4. Propiedades de bordes y sombras

Permiten añadir contornos, redondear esquinas o dar sensación de relieve con sombras.

  • border: grosor, estilo y color. Ej: border: 2px solid black;
  • border-radius: esquinas redondeadas. Ej: border-radius: 10px;
  • box-shadow: sombras proyectadas. Ej: box-shadow: 0 2px 6px rgba(0,0,0,0.2);
img {
  border: 3px solid #333;
  border-radius: 50%;
  box-shadow: 0 4px 10px rgba(0,0,0,.3);
}

3.5. Otras propiedades

Existen muchísimas más propiedades CSS: algunas afectan al comportamiento de las tablas, otras al scroll, al diseño responsive, a las animaciones, a la accesibilidad, etc. No es posible cubrirlas todas en este material. Lo importante es comprender las más usadas y saber cómo encontrar las demás en la documentación oficial.

Puedes consultar la lista completa y actualizada de propiedades CSS en la W3C.

Consejo: domina primero las propiedades de tipografía, color/fondo, caja y bordes/sombras. Con ellas podrás resolver la mayoría de los problemas de maquetación. Las demás las irás aprendiendo según las necesites.

4. Unidades, funciones y color

En CSS, las unidades determinan cómo se miden las longitudes, tamaños de fuente, márgenes o anchos de elementos. Comprender qué unidades usar en cada situación es esencial para lograr diseños consistentes, flexibles y accesibles. Un error común en principiantes es usar siempre px, lo que impide escalabilidad en zoom o en dispositivos diferentes. Alternativas como rem, % o vw/vh permiten que los elementos se adapten a la configuración del usuario y al entorno.

4.1 Unidades en CSS

CategoríaUnidadesUso recomendado
Absolutas px Iconos, bordes finos, sombras; evita basar tipografía en px para no romper zoom.
Relativas a fuente em, rem rem para escalado global (tamaños y espacios); em para componentes que escalen desde su propio contexto.
Relativas al contenedor %, ch, ex % para anchuras/alturas según padre; ch para medidas de texto (ej. ancho de línea ~ 60ch).
Viewport vw, vh, vmin, vmax Bloques que respondan al tamaño de la ventana (héroes, tipografía fluida). Ojo en móvil con la barra del navegador.
Viewport modernos dvh, svh, lvh dvh (dynamic) ajusta altura útil real en móvil; svh/lvh para situaciones específicas.
Consultas de contenedor cqw, cqh, cqi, cqb Cuando usas container queries, estas unidades responden al tamaño del contenedor, no del viewport.

Regla práctica: usa rem para escalado global; em dentro de componentes; % para tamaños relativos al padre; clamp() + vw para tipografía fluida.

4.2 Funciones útiles

Además de elegir la unidad adecuada, CSS nos ofrece funciones matemáticas que permiten calcular valores dinámicos, establecer límites flexibles y crear escalas fluidas. Piensa en ellas como "calculadoras integradas" en tu CSS que trabajan en tiempo real.

Estas funciones evitan depender de múltiples media queries y facilitan patrones de diseño más elegantes y mantenibles. ¿Por qué son importantes? Porque permiten que tu diseño se adapte automáticamente sin tener que escribir decenas de reglas diferentes para cada tamaño de pantalla.

Las tres funciones esenciales

1. calc() - La calculadora de CSS

calc() te permite hacer operaciones matemáticas mezclando diferentes unidades. Es como tener una calculadora dentro de tu CSS que funciona en tiempo real.

¿Cuándo usarla?

  • Cuando necesitas restar padding de un ancho: width: calc(100% - 2rem)
  • Para centrar elementos con márgenes calculados
  • Cuando quieres combinar unidades fijas (px) con relativas (%)
/* Ejemplo: ancho completo menos margen lateral */
  .container {
    width: calc(100% - 40px);
    /* Toma el 100% del ancho y le resta 40 píxeles */
  }

  /* Ejemplo: centrado con altura dinámica */
  .hero {
    height: calc(100vh - 80px);
    /* Altura completa de la ventana menos 80px de la barra de navegación */
  }

2. min() y max() - Límites inteligentes

Estas funciones toman el valor más pequeño (min) o más grande (max) de una lista de valores. Son "límites duros" que garantizan que un elemento nunca sea demasiado grande o demasiado pequeño.

Piénsalo así:

  • min(A, B) → "Usa el que sea MÁS PEQUEÑO entre A y B"
  • max(A, B) → "Usa el que sea MÁS GRANDE entre A y B"
/* min() - El elemento nunca será más ancho que 800px */
  .card {
    width: min(100%, 800px);
    /* Si la pantalla es menor a 800px → usa 100%
       Si la pantalla es mayor a 800px → usa 800px */
  }

  /* max() - El texto nunca será más pequeño que 14px */
  p {
    font-size: max(14px, 1rem);
    /* Si 1rem es menor que 14px → usa 14px
       Si 1rem es mayor que 14px → usa 1rem */
  }

3. clamp() - Escalado fluido con límites

clamp(mínimo, ideal, máximo) es la función más poderosa: permite que un valor crezca y se reduzca de forma fluida, pero nunca por debajo del mínimo ni por encima del máximo.

Estructura: clamp(valor_mínimo, valor_preferido, valor_máximo)

  • Valor mínimo: "No puede ser más pequeño que esto" (ej. 1rem)
  • Valor preferido: "Esto es lo que quiero idealmente" (ej. 2vw + 0.5rem)
  • Valor máximo: "No puede ser más grande que esto" (ej. 3rem)

¿Cómo funciona? El navegador calcula el valor preferido y, si cae dentro del rango mínimo-máximo, lo usa. Si es menor que el mínimo, usa el mínimo. Si es mayor que el máximo, usa el máximo.

/* Tipografía que crece con la pantalla pero con límites */
  h1 {
    font-size: clamp(1.5rem, 2.2vw + 0.5rem, 3rem);
    /*
     - En móvil pequeño: 1.5rem (mínimo)
     - En tablet: se calcula 2.2vw + 0.5rem (crece gradualmente)
     - En pantalla grande: 3rem (máximo)
     No necesitas media queries, ¡se adapta solo!
    */
  }

4.3 Colores y contrastes

En diseño web no basta con elegir colores "bonitos": es fundamental que los colores sean consistentes, accesibles y fáciles de mantener. Un error común de principiantes es elegir colores de forma aleatoria sin un sistema, lo que dificulta crear variaciones coherentes (como botones hover, alertas, modos oscuros, etc.).

CSS ofrece diferentes modelos de color (HEX, RGB, HSL, OKLCH), cada uno con sus ventajas. Comprenderlos permite crear paletas escalables y garantizar suficiente contraste para que todo el contenido sea legible, incluso para usuarios con baja visión o en pantallas con mala calibración.

Los modelos de color explicados desde cero

1. HEX (Hexadecimal) - El clásico

Es el formato más tradicional. Usa 6 caracteres hexadecimales (0-9, A-F) para representar Rojo, Verde y Azul. 

/* Estructura: #RRGGBB */
  color: #1f1769;
  /*
    1f = cantidad de ROJO (31 en decimal)
    17 = cantidad de VERDE (23 en decimal)
    69 = cantidad de AZUL (105 en decimal)
  */

  /* Con transparencia (8 caracteres): #RRGGBBAA */
  color: #1f176980;  /* El '80' al final = 50% de opacidad */

Ventajas: Compacto, ampliamente soportado, fácil de copiar/pegar

Desventajas: Difícil de leer y modificar (¿cómo haces este azul más claro sin calculadora?)

2. RGB(a) - Rojo, Verde, Azul

Similar a HEX pero con números decimales del 0 al 255. Más legible que HEX pero sigue siendo poco intuitivo para crear variaciones. 

/* Sintaxis moderna (sin comas, con /) */
  color: rgb(31 23 105);

  /* Con transparencia (canal alfa) */
  background: rgb(31 23 105 / 0.85);  /* 85% de opacidad */
  background: rgb(31 23 105 / 50%);   /* También puedes usar porcentaje */

Ventajas: Números legibles, canal alfa directo

Desventajas: Difícil crear variaciones (¿cómo haces este color más saturado?)

3. HSL - Tono, Saturación, Luminosidad

Este es el gran cambio.HSL piensa en colores como lo hacemos los humanos:

  • H (Hue/Tono): Qué color es (0-360 grados en una rueda de color)
    • 0° / 360° = Rojo
    • 120° = Verde
    • 240° = Azul
    • 60° = Amarillo
    • 180° = Cyan
    • 300° = Magenta
  • S (Saturation/Saturación): Qué tan intenso es el color (0-100%)
    • 0% = Gris (sin color)
    • 50% = Color moderado
    • 100% = Color máximo, vibrante
  • L (Lightness/Luminosidad): Qué tan claro u oscuro es (0-100%)
    • 0% = Negro total
    • 50% = Color "puro"
    • 100% = Blanco total
/* Sintaxis: hsl(tono saturación% luminosidad%) */
  --azul-base: hsl(240 80% 50%);
  /*
    240 = Azul (posición en la rueda de color)
    80% = Muy saturado (vibrante)
    50% = Luminosidad media (ni muy claro ni muy oscuro)
  */

  /* Con transparencia */
  --azul-translucido: hsl(240 80% 50% / 0.5);  /* 50% transparente */

  /* Crear variaciones es fácil: */
  --azul-oscuro: hsl(240 80% 30%);   /* Bajo la luminosidad */
  --azul-claro: hsl(240 80% 80%);    /* Subo la luminosidad */
  --azul-pastel: hsl(240 40% 70%);   /* Bajo saturación y subo luminosidad */
  --azul-gris: hsl(240 10% 50%);     /* Muy poca saturación = grisáceo */

¿Por qué es mejor para principiantes?

  • Cambiar la luminosidad es trivial (solo modifica el tercer número)
  • Crear versiones claras/oscuras del mismo color es inmediato
  • Perfecto para estados hover, active, disabled
  • Ideal para crear paletas completas manteniendo el mismo tono

4. OKLCH

OKLCH es un modelo perceptualmente uniforme. ¿Qué significa esto? Que si aumentas la luminosidad en 10%, el ojo humano percibe el mismo incremento independientemente del color base. En HSL, un amarillo al 50% de luminosidad se ve mucho más claro que un azul al 50%.

Estructura: oklch(Luminosidad% Croma Tono)

  • L (Lightness): 0% = negro, 100% = blanco (similar a HSL)
  • C (Chroma/Croma): Intensidad del color (0 = gris, 0.4 = muy intenso). No usa porcentaje, es un número decimal (ej: 0.15, 0.25)
  • H (Hue/Tono): Ángulo en la rueda de color (0-360, como HSL)
/* Sintaxis: oklch(luminosidad% croma tono) */
  --violeta: oklch(60% 0.12 260);
  /*
    60% = Luminosidad media-alta
    0.12 = Croma moderado (no demasiado saturado)
    260 = Violeta/azul (grados en la rueda)
  */

  /* Crear variaciones perceptualmente uniformes */
  --violeta-oscuro: oklch(40% 0.12 260);  /* Mismo croma, menos luminosidad */
  --violeta-claro: oklch(80% 0.12 260);   /* Mismo croma, más luminosidad */
  --violeta-intenso: oklch(60% 0.25 260); /* Más croma = más saturado */

Ventajas sobre HSL:

  • Colores más consistentes visualmente
  • Mejor para generar escalas de grises y tonos neutros
  • Gradientes más suaves y naturales

Desventajas:

  • Soporte en navegadores desde 2023
  • Necesitas un fallback para navegadores antiguos
/* Con fallback para navegadores antiguos */
  .button {
    background: hsl(260 60% 50%);           /* Fallback para navegadores viejos */
    background: oklch(60% 0.15 260);        /* Navegadores modernos usan esto */
  }

4.4 Patrones prácticos y Tokens de diseño

Ahora que conoces las unidades, funciones y colores, es momento de aprender a organizarlos de forma profesional. En proyectos reales, no defines valores∫ cada vez que los necesitas. En su lugar, usas un sistema de diseño basado en tokens.

¿Qué son los "tokens" de diseño?

Los tokens de diseño son valores reutilizables con nombres semánticos que defines una vez y usas en todo tu proyecto. Son la base de tu diseño.

Piénsalo así:

  • Sin tokens: Cada vez que necesitas un espacio escribes padding: 16px, luego 15px, luego 17px... No hay consistencia.
  • Con tokens: Defines --space-3: 1rem una vez y lo usas en 50 lugares. Si decides cambiarlo, solo modificas UN valor.

Tipos de tokens más comunes

1. Tokens de ESPACIADO (spacing)

Definen los márgenes, paddings y gaps de forma consistente. En lugar de usar valores aleatorios, creas una escala predefinida. 

/* Sistema de espaciado con escala */
  :root {
    --space-1: 0.25rem;   /* 4px  - Espacios mínimos */
    --space-2: 0.5rem;    /* 8px  - Espacios pequeños */
    --space-3: 0.75rem;   /* 12px - Espacios medianos */
    --space-4: 1rem;      /* 16px - Espacios estándar */
  }

  /* USO en componentes */
  .button {
    padding: var(--space-2) var(--space-4);
    /* 8px arriba/abajo, 16px izquierda/derecha */
  }

  .card {
    padding: var(--space-4);
    gap: var(--space-3);
    /* Separación interna de 16px, gaps de 12px */
  }

  }

Ventajas:

  • Consistencia visual: todos los espacios siguen la misma escala
  • Fácil de ajustar: cambias --space-3 y se actualiza en todo el sitio
  • Más rápido de escribir: var(--space-3) vs recordar si eran 12px o 14px

Escala recomendada para principiantes:

Usa múltiplos de 4px o 8px. Es una convención de la industria porque son fáciles de recordar y crear ritmo visual.

2. Tokens de RADIO/BORDES REDONDEADOS (border-radius)

Definen cuánto redondear las esquinas de botones, tarjetas, inputs, etc. 

:root {
    --radius-1: 0.25rem;  /* 4px  - Bordes sutiles */
    --radius-2: 0.5rem;   /* 8px  - Bordes medianos */
    --radius-3: 0.75rem;  /* 12px - Bordes redondeados */
    --radius-4: 1rem;     /* 16px - Bordes muy redondeados */
  }

  .button {
    border-radius: var(--radius-2);
    /* Todos los botones tienen el mismo redondeo */
  }

  .card {
    border-radius: var(--radius-3);
    /* Las tarjetas un poco más redondeadas */
  }

3. Tokens de TAMAÑO DE FUENTE (font-size)

Definen una escala tipográfica coherente. Los números (300, 400, 500...) siguen la convención de pesos de fuente. 

:root {
    --fs-300: 0.875rem;   /* 14px - Texto pequeño (labels, captions) */
    --fs-400: 1rem;       /* 16px - Texto base (párrafos) */
    --fs-500: 1.125rem;   /* 18px - Texto destacado */
    --fs-600: 1.25rem;    /* 20px - Subtítulos pequeños */
    --fs-700: 1.5rem;     /* 24px - Subtítulos (h3) */
    --fs-800: 2rem;       /* 32px - Títulos (h2) */
    --fs-900: 2.5rem;     /* 40px - Títulos grandes (h1) */
  }

  /* USO */
  body {
    font-size: var(--fs-400);  /* Base: 16px */
  }

  small, .caption {
    font-size: var(--fs-300);  /* Texto pequeño */
  }

  h1 {
    font-size: var(--fs-900);
  }


  }

Truco: Usa escalas fluidas con clamp()

:root {
    /* Tipografía que crece con la pantalla */
    --fs-400: clamp(0.9rem, 0.9rem + 0.2vw, 1rem);
    --fs-800: clamp(1.75rem, 1.5rem + 1vw, 2.5rem);
    /* Móvil: 1.75rem → Desktop: 2.5rem */
  }

5. Cascada, herencia y especificidad

Cuando varios estilos intentan aplicarse sobre el mismo elemento, el navegador debe decidir qué regla gana. Entender cómo toma esta decisión es fundamental para escribir CSS predecible, limpio y mantenible.

5.1. La Cascada - ¿Qué regla gana cuando hay conflicto?

El término "cascada" viene de "caer en cascada", como una cascada de agua. Se refiere al orden en que el navegador procesa y prioriza las reglas cuando hay conflicto.

¿Qué es un conflicto? Cuando dos o más reglas intentan cambiar la misma propiedad del mismo elemento. Por ejemplo: 

/* Regla 1 */
  p { color: blue; }

  /* Regla 2 */
  p { color: red; }

El navegador decide siguiendo este orden (de mayor a menor prioridad):

  1. Origen de la regla

    Existen tres fuentes de CSS:

    • User Agent (navegador): Estilos por defecto del navegador (ej. los enlaces son azules por defecto)
    • Autor : Tu CSS personalizado
    • Usuario: CSS que el usuario configure en su navegador (poco común)

    Prioridad: Navegador < Autor < Usuario

  2. Importancia (!important) 
    p { color: blue !important; }  /* Esta gana */
  p { color: red; }

    Cuidado con !important

    !important es como gritar en una conversación: funciona, pero hace que todo sea más difícil de mantener. Úsalo solo en casos excepcionales:

    • Correcto: Sobrescribir estilos de librerías externas que no puedes modificar
    • Incorrecto: Usarlo porque "no sé por qué no funciona mi CSS"
  3. Especificidad

    Mide "qué tan preciso" es tu selector. Selectores más específicos ganan.

  4. Orden de aparición

    Si todo lo anterior empata, gana la última regla que aparezca en el código.

    p { color: blue; }
  p { color: green; }
  p { color: red; }   /* ← Esta gana (es la última) */

Ejemplo visual del proceso de cascada

/* Archivo: estilos.css */

  /* Paso 1: Navegador tiene estilos por defecto */
  /* p { color: black; } (implícito del navegador) */

  /* Paso 2: Tú defines tu regla (gana sobre el navegador) */
  p { color: blue; }

  /* Paso 3: Otra regla más abajo (gana por orden) */
  p { color: green; }

  /* Paso 4: Regla con mayor especificidad (gana por especificidad) */
  .articulo p { color: purple; }

  /* Paso 5: !important (gana sobre todo) */
  p { color: red !important; }

  /* Resultado final: rojo  */

5.2. La Herencia - Propiedades que "pasan" de padres a hijos

La herencia es el mecanismo por el cual algunos estilos aplicados a un elemento se transmiten automáticamente a sus elementos hijos en el DOM.

Propiedades que SÍ se heredan

Categoría Propiedades Razón
Tipografía font-family, font-size, font-weight, font-style, line-height Quieres que todo el texto tenga la misma fuente por defecto
Texto color, text-align, text-transform, letter-spacing El color y alineación suelen ser coherentes en un contenedor
Visibilidad visibility, cursor Si un contenedor es invisible, sus hijos también
Listas list-style, list-style-type Todas las listas dentro heredan el estilo

Propiedades que NO se heredan

Las propiedades relacionadas con el modelo de caja y el layout NO se heredan, porque cada elemento necesita controlar sus propias dimensiones y espaciado.

Categoría Propiedades Razón
Espaciado margin, padding Cada elemento necesita su propio espacio
Bordes border, border-radius No quieres que todos los hijos tengan el mismo borde
Dimensiones width, height, max-width Cada elemento tiene su propio tamaño
Fondos background, background-color Cada elemento puede tener su propio fondo
Posicionamiento position, top, left, z-index Cada elemento controla su posición
Display display, flex, grid Cada elemento define su tipo de caja

Controlar la herencia de forma explícita

A veces quieres forzar o romper la herencia. CSS te da palabras clave especiales:

Palabra clave Qué hace Cuándo usarla
inherit Fuerza a heredar del elemento padre, incluso propiedades que normalmente NO heredan Cuando quieres que un borde o padding se herede
initial Restablece al valor inicial de la especificación CSS (no del navegador) Para "resetear" una propiedad a su estado original
unset Si la propiedad hereda → actúa como inherit
Si NO hereda → actúa como initial		 Para "limpiar" estilos sin saber si hereda o no
revert Vuelve al estilo que tendría según la hoja del navegador Para restaurar estilos por defecto del navegador

Ejemplos prácticos de control de herencia

/* ===== Ejemplo 1: Forzar herencia con inherit ===== */

  .card {
    color: darkblue;
    border: 2px solid gray;
  }

  .card a {
    color: inherit;
    /* Los enlaces heredan el color del .card (darkblue)
       Por defecto, los enlaces son azules, pero aquí forzamos
       que usen el color del padre */
  }

  /* ===== Ejemplo 2: Resetear con initial ===== */

  .special-heading {
    font-size: initial;
    /* Vuelve al tamaño por defecto de CSS (medium, ~16px)
       Ignora cualquier herencia del body o padres */
  }

  /* ===== Ejemplo 3: Limpiar con unset ===== */

  .reset-all {
    all: unset;
    /* Limpia TODAS las propiedades:
       - Las que heredan → heredan del padre
       - Las que no → vuelven a initial */
  }

  /* ===== Ejemplo 4: Restaurar estilos del navegador con revert ===== */

  .link-normal {
    all: revert;
    /* El enlace vuelve a tener el estilo azul+subrayado
       del navegador, ignorando todo tu CSS */
  }

5.3. La Especificidad - ¿Qué selector es más "específico"?

La especificidad mide cuán preciso es un selector. Cuanto más específico sea, más peso tendrá su regla frente a otras.

Niveles de especificidad (de menor a mayor)

Nivel Selector Puntos Ejemplo
1. Universal * 0 * { margin: 0; }
2. Elementos/tipo p, div, h1 1 p { color: blue; }
3. Clases, atributos, pseudoclases .clase, [type], :hover 10 .button { color: red; }
4. IDs #id 100 #header { color: green; }
5. Estilos en línea style="..." 1000 <p style="color: orange">
6. !important !important ∞ (infinito) p { color: red !important; }

Cómo se calculan los puntos (sistema simplificado)

El navegador cuenta cuántos selectores de cada tipo hay y los suma:

/* Ejemplo 1: Solo tipo (elemento) */
  p { color: blue; }
  /* Puntuación: 0-0-1 (0 IDs, 0 clases, 1 elemento) */

  /* Ejemplo 2: Clase */
  .article { color: green; }
  /* Puntuación: 0-1-0 (0 IDs, 1 clase, 0 elementos) */
  /* GANA sobre el ejemplo 1 (10 > 1) */

  /* Ejemplo 3: Clase + tipo */
  .article p { color: purple; }
  /* Puntuación: 0-1-1 (0 IDs, 1 clase, 1 elemento = 11) */
  /* GANA sobre el ejemplo 2 (11 > 10) */

  /* Ejemplo 4: ID */
  #main { color: red; }
  /* Puntuación: 1-0-0 (1 ID, 0 clases, 0 elementos = 100) */
  /* GANA sobre todos los anteriores (100 > 11) */

  /* Ejemplo 5: Múltiples clases */
  .card.featured { color: orange; }
  /* Puntuación: 0-2-0 (0 IDs, 2 clases, 0 elementos = 20) */

  /* Ejemplo 6: Selector complejo */
  #header .nav .menu li a:hover { color: pink; }
  /* Puntuación: 1-3-2 (1 ID, 3 clases/pseudoclases, 2 elementos = 132) */

Regla de oro profesional:

  • Usa clases para el 90% de tu CSS
  • Mantén selectores cortos (1-2 niveles máximo)
  • Evita IDs en CSS (úsalos solo para JavaScript o enlaces internos)
  • Evita !important salvo casos excepcionales
  • Si necesitas sobrescribir, añade una clase más específica, no uses !important

6. Modelo de caja (Box Model)

En CSS, todo elemento se representa como una caja. Esa caja no es solo “un rectángulo con ancho y alto”: está compuesta por capas (contenido, padding, border y margin) y se ve afectada por su tipo de visualización (display), por cómo calculamos los tamaños (box-sizing) y por reglas especiales como el colapso de márgenes. Dominar el modelo de caja es la base para maquetar con precisión.

Capas de dentro a fuera: contenido → padding → border → margin. El padding y el border suman “tamaño real” de la caja; el margin separa esta caja de las demás.

6.1. Partes de la caja y cálculo de tamaño

Por defecto (box-sizing: content-box), width y height definen solo el área de contenido. El tamaño total que ocupa la caja en el layout se calcula así: 

TOTAL WIDTH = margin-left + border-left + padding-left + content-width + padding-right + border-right + margin-right
TOTAL HEIGHT = margin-top + border-top + padding-top + content-height + padding-bottom + border-bottom + margin-bottom

Con box-sizing: border-box, el width/height incluyen contenido + padding + border (el tamaño total es más fácil de predecir, muy útil en componentes y grids).

Buena práctica global: *{ box-sizing: border-box; } o, mejor, *, *::before, *::after{ box-sizing: border-box; }.

Ejemplo A · content-box vs border-box

.c1{
  box-sizing: content-box;
  width: 200px; padding: 20px; border: 5px solid #333; margin: 8px;
}
.c2{
  box-sizing: border-box;
  width: 200px; padding: 20px; border: 5px solid #333; margin: 8px;
}
<div class="c1">content-box: el total > 200px</div>
<div class="c2">border-box: el total = 200px + márgenes</div>

6.2. Anchuras, alturas y valores auto

  • Bloques (display: block): por defecto ocupan todo el ancho disponible (como si width: auto) y su altura se ajusta al contenido (height: auto).
  • Elementos en línea (display: inline): ignoran width/height; su tamaño depende del contenido y del flujo de línea.
  • Reemplazados (<img>, <video>, <canvas>): tienen un tamaño intrínseco y sí respetan width/height aunque sean inline.

Ejemplo B · centrar un bloque fijo

.card{
  width: 320px;
  margin: 1rem auto;         /* auto en los laterales centra en el contenedor */
  padding: 1rem;
  border: 1px solid #ddd;
}

6.3. Márgenes: colapso (margin collapsing)

En el flujo normal, los márgenes verticales de cajas de bloque pueden colapsar: en lugar de sumarse, se “superponen” y prevalece el mayor. Esto ocurre entre elementos hermanos adyacentes, entre un padre y su primer/último hijo, y en cajas vacías.

Ejemplo C · colapso entre hermanos

p{ margin: 16px 0; }
/* Entre dos <p> verticales (uno debajo del otro) no hay 32px sino 16px: colapsan. */

No colapsa si entre las cajas hay padding o border, si el hijo está posicionado, si el contenedor crea un nuevo “contexto” de formato (p. ej., overflow:auto, display: flow-root), y no colapsa en elementos flex o grid.

Cómo “romper” el colapso

  • Añadir padding-top o border-top al contenedor.
  • Forzar un nuevo contexto de formateo: overflow: auto o display: flow-root.
.section{
  /* Solución limpia moderna */
  display: flow-root;         /* evita colapso y limpia floats */
  padding-top: 1rem;
}

6.4. display y su efecto en la caja

  • block: rompe línea antes y después; respeta width/height, margin vertical colapsa en flujo normal.
  • inline: no rompe línea; ignora width/height; respeta padding/border pero no empuja líneas verticalmente (usa line-height y vertical-align).
  • inline-block: se comporta como inline en el flujo, pero admite width/height como un bloque.
  • flow-root: crea un nuevo contexto de formateo de bloque (BFC). Útil para evitar colapso de márgenes y “encerrar” floats.
  • flex/grid: cambian el modelo de distribución; sus ítems no colapsan márgenes verticales con el contenedor.

Ejemplo D · inline vs inline-block

.tag{ display:inline; padding: .25rem .5rem; border: 1px solid #888; }
.btn{ display:inline-block; width:140px; text-align:center; padding:.5rem; }

6.5. Propiedades lógicas (compatibles con escritura RTL/vertical)

En lugar de left/right/top/bottom, usa propiedades lógicas que se adaptan al writing-mode y a idiomas RTL:

  • padding-inline, margin-inline (ejes horizontal lógico)
  • padding-block, margin-block (eje vertical lógico)
  • border-inline, border-block
.card{
  padding-block: 1rem;        /* arriba/abajo en el eje del bloque */
  padding-inline: 1.25rem;    /* inicio/fin en el eje inline */
  border-inline: 1px solid #ddd;
}

6.6. Fondos, bordes y sombras: áreas de pintura

El color/imagen de fondo puede “pintarse” en distintas áreas; controla esto con background-clip:

  • border-box (por defecto): fondo bajo el borde.
  • padding-box: fondo solo bajo contenido + padding.
  • content-box: fondo solo bajo el contenido.
.box{
  background: linear-gradient(45deg, #f9c 0%, #9cf 100%);
  border: 6px solid #333;
  padding: 16px;
  background-clip: padding-box;   /* el fondo no “se mete” bajo el borde */
}

box-shadow agrega profundidad sin alterar el tamaño; outline dibuja un contorno externo que no ocupa espacio (ideal para foco accesible): 

.focusable:focus-visible{
  outline: 2px solid #1f6feb;
  outline-offset: 2px;          /* separa el contorno de la caja */
}

6.7. Desbordamiento (overflow) y recorte

  • overflow: visible (por defecto): el contenido que se sale se ve.
  • hidden: recorta sin barras.
  • auto/scroll: muestra barras cuando haga falta/siempre.

Texto con puntos suspensivos

.ellipsis{
  width: 220px;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

Performance: cuando animes cajas, prioriza transform y opacity. Evita animar width/height (fuerzan recálculo de layout).

7. Layout y posicionamiento en CSS (visión completa y práctica)

Diseñar una página no es “mover cajas a ojo”, el navegador sigue reglas claras para crear y colocar cajas. Primero sitúa todo en el flujo normal (según el display de cada elemento). Luego, si lo pides, saca elementos del flujo (por ejemplo, position:absolute o fixed) o reorganiza los hijos con sistemas de layout modernos (Flexbox y Grid). Esta sección es tu guía de campo: en qué orden pensar, qué propiedad usar y por qué.

7.1. display y flujo normal

En CSS, cada elemento de HTML se representa como una caja. Esa caja se inserta en el documento siguiendo el flujo normal, que es la forma en que el navegador coloca las cajas por defecto sin reglas de posicionamiento avanzadas.

El flujo normal distingue entre dos tipos fundamentales de cajas:

  • Cajas de bloque (block): Ocupan todo el ancho disponible del contenedor y empujan el siguiente elemento hacia una línea nueva. Son ideales para organizar secciones grandes de la página, ya que respetan propiedades como width, height, margin, padding y border. Ejemplos: <div>, <p>, <section>, <article>.
  • Cajas en línea (inline): Se colocan unas detrás de otras dentro del mismo renglón, como si fueran parte del texto. width y height no les afectan directamente: su tamaño depende del contenido. Sí respetan padding y margin, pero solo en los laterales horizontalmente, no verticalmente. Ejemplos: <span>, <a>, <strong>.

Además de estos dos tipos básicos, CSS nos ofrece otros valores de display que mezclan o extienden comportamientos:

  • inline-block: Es un “punto intermedio”. Se comporta como inline en el flujo (no fuerza salto de línea), pero sí respeta width y height. Muy útil para botones, iconos o elementos que deben fluir en línea pero conservar medidas fijas.
  • flow-root: Crea un nuevo Block Formatting Context (BFC). Esto significa que la caja se convierte en un “contenedor independiente” que evita problemas de colapso de márgenes y que “envuelve” correctamente a elementos flotados. Es una solución moderna y limpia para contener secciones sin añadir hacks.
  • flex: Activa el modelo de Flexbox, pensado para distribuir hijos en un único eje (fila o columna), alinear vertical y horizontalmente y repartir espacio sin necesidad de cálculos manuales.
  • grid: Activa el modelo de Grid Layout, diseñado para componer en dos ejes simultáneamente. Permite crear cuadrículas de filas y columnas explícitas, asignar áreas y reorganizar contenido de forma responsive con gran control.

Consejo: la mayoría de elementos estructurales (<div>, <section>, <p>) son block por defecto. Los elementos de texto (<span>, <a>, <em>) son inline. Aprende a reconocerlos: cambiar display es el primer paso para construir cualquier layout.

Ejemplo práctico

<div>Bloque 1 (ocupa toda la línea)</div>
  <div>Bloque 2 (aparece debajo)</div>
  <p>Texto con <span>elemento en línea</span> en medio.</p>
div{ display:block; background:#fee2e2; margin-bottom:.5rem; }
  span{ display:inline; background:#bfdbfe; }

Regla mental: empieza por flujo normal. Si necesitas alinear o repartir espacio en un único eje → Flex. Si necesitas controlar filas y columnas de forma explícita → Grid. El posicionamiento clásico solo cuando realmente haga falta.

7.2. Posicionamiento clásico: position y el “containing block”

La propiedad position determina cómo se calcula la posición de una caja en el documento. Por defecto, todas las cajas se colocan en el flujo normal. Cuando cambiamos position, podemos ajustar su ubicación con las coordenadas top, right, bottom y left.

La clave está en entender el containing block: el “contenedor de referencia” respecto al cual se calculan esas coordenadas. Para un elemento absolute, este será el primer ancestro con position distinto de static. Si no encuentra ninguno, tomará como referencia el viewport (la ventana del navegador).

Valores principales de position

  • static (valor por defecto): El elemento está en el flujo normal y top/right/bottom/left no tienen efecto. Ejemplo: la mayoría de elementos sin estilos explícitos.
  • relative: El elemento permanece en el flujo (su hueco no se pierde), pero podemos moverlo con coordenadas. Además, convierte al elemento en contenedor de referencia para hijos absolute.
  • absolute: El elemento se saca del flujo: los hermanos lo ignoran como si no existiera. Se posiciona con coordenadas respecto a su contenedor posicionado más cercano, o al viewport si no existe ninguno.
  • fixed: Similar a absolute, pero siempre respecto al viewport. Se queda fijo en pantalla aunque hagamos scroll. Ideal para menús flotantes, botones “volver arriba” o banners persistentes.
  • sticky: Un híbrido entre relative y fixed. El elemento ocupa su hueco en el flujo, pero al hacer scroll se “pega” al borde definido (top, bottom, etc.) hasta que su contenedor se acaba. Muy útil para cabeceras o menús que acompañan parcialmente.

Truco: siempre que uses absolute, añade position: relative; al contenedor padre si quieres que el hijo se posicione dentro de él. Así evitas que “vuele” hasta el viewport.

Ejemplo 1 · Insignia dentro de una tarjeta (absolute + relative)

.card{
  position: relative; /* crea contenedor de referencia */
  padding:1rem; border:1px solid #ddd; border-radius:8px;
}
.card__badge{
  position:absolute; top:.5rem; right:.5rem;
  padding:.25rem .5rem; background:#1f2937; color:#fff;
  border-radius:999px; font-size:.875rem;
}
<article class="card">
  <span class="card__badge">Nuevo</span>
  <h3>Título</h3><p>Contenido...</p>
</article>

Ejemplo 2 · Cabecera pegajosa (sticky)

.sticky-bar{
  position: sticky;
  top: 0;                 /* umbral: se pega al llegar al top */
  z-index: 10;            /* asegúrate de que quede por encima */
  background:#fff; border-bottom:1px solid #eee;
}

Ejemplo 3 · Botón “volver arriba” fijo

.back-to-top{
  position: fixed;
  right: 1rem; bottom: 1rem;
  background:#2563eb; color:#fff;
  padding:.6rem .9rem; border-radius:6px;
}

z-index y apilado: z-index controla qué elemento queda por encima cuando se solapan. Pero solo funciona en elementos posicionados (relative, absolute, fixed, sticky) o en los que crean un stacking context (por ejemplo, con transform o opacity < 1). Si un elemento no “sube” aunque le pongas z-index:9999, probablemente un ancestro ha creado su propio contexto: revisa si tiene transform o opacity.

7.3. Flexbox: Distribución y alineación en un eje

Flexbox es un modelo de disposición unidimensional: sirve para colocar elementos a lo largo de un eje —sea horizontal (fila) o vertical (columna)—. Además, adapta automáticamente el tamaño, la alineación y el orden de los ítems según el espacio disponible. Es ideal para:

  • Menús de navegación o barras de herramientas.
  • Galerías de tarjetas, listas adaptables.
  • Centrado de texto o formularios de forma sencilla.

Aprende a usarlo bien para maquetar con fluidez: los conceptos clave son el eje principal (main axis) y el eje cruzado (cross axis); saber cuál se mueve con qué propiedad marca la diferencia.

Flexbox sigue un algoritmo muy potente. Una vez manejes flex-direction, justify-content y align-items, sabrás resolver la mayoría de problemas de layout unidimensional. El resto es perfeccionar con flex-wrap, flex y el orden visual.

7.3.1. Contenedor flex – Propiedades clave

.contenedor {
  display: flex;                /* activa Flexbox */
  flex-direction: row;          /* eje principal: row, row-reverse, column, column-reverse */
  flex-wrap: wrap;              /* permite que los ítems salten de línea */
  gap: 1rem;                    /* hueco entre ítems */
  justify-content: space-between; /* alineación en el eje principal */
  align-items: center;          /* alineación en el eje cruzado */
  align-content: start;         /* alineación cuando hay varias líneas */
}

7.3.2. Ítems flex – Control de espacio y orden

.item {
  flex: 1 1 200px;              /* grow | shrink | basis */
  /* equivale a:
     flex-grow: 1;
     flex-shrink: 1;
     flex-basis: 200px;
  */
  flex-basis: 200px;            /* tamaño deseado antes de distribuir espacio */
  order: 0;                     /* reordena visualmente, cuidado con la accesibilidad */
  align-self: auto;             /* permite sobreescribir align-items en este ítem */
  min-width: 0;                 /* evita que contenido impida que encaje bien */
}

7.3.3. Explicación de propiedades esenciales

  • flex-direction: define si los ítems se organizan en fila o columna (y su orden).
  • justify-content: gestiona el espaciado y alineación de grupo en el eje principal (start, center, end, space-between, space-around, space-evenly).
  • align-items: alinea cada ítem individual en el eje cruzado (stretch, center, flex-start, flex-end, baseline).
  • gap: crea separación física entre ítems sin margen, más limpio y predecible.
  • flex-wrap: controla si los ítems deben adaptarse en una sola línea o fluir a varias (wrap, nowrap, wrap-reverse).
  • flex shorthand: combina crecimientos, encogimientos y tamaño base con un solo valor.
  • order: permite reorganizar ítems visualmente sin alterar el HTML—but use with care!

7.3.4. Ejemplos comunes con explicaciones

Navbar con botón CTA a la derecha
<nav class="nav">
  <a href="#">Inicio</a>
  <a href="#">Acerca</a>
  <span class="spacer"></span>
  <a class="btn" href="#">Entrar</a>
</nav>
.nav {
  display: flex;
  align-items: center;
}
.spacer {
  flex: 1; /* empuja el CTA a la derecha */
}
Centrado completo dentro de un contenedor
.centered {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 200px;
}
Galería fluida con tarjetas adaptables
.gallery {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
}
.gallery .card {
  flex: 1 1 220px;
}

7.3.5. Errores comunes y cómo evitarlos

  • No poner min-width: 0 en ítems con contenido largo → rompe el layout.
  • Usar order para maquetar sin pensar en accesibilidad → desorden visual vs DOM.
  • Ignorar que flex-basis puede comportarse distinto que width en imágenes y elementos reemplazados.
  • Olvidar gap y saturar con margin manual → menos control y más errores.

7.3.6. Mini-reto práctico

  1. Convierte un menú horizontal en versión móvil con ítems que se envuelven en varias líneas usando flex-wrap.
  2. Haz que un grupo de tres tarjetas ocupe todo el ancho disponible por igual (flex-grow).
  3. Reordena visualmente tres ítems sin cambiar el HTML usando order.

Cuándo usar Flex: barras, menús, formularios, filas/columnas simples, componentes donde la prioridad es la alineación en un único eje.

7.4. Grid: composición en dos ejes (filas y columnas)

CSS Grid es un sistema de layout bidimensional: te permite colocar y alinear elementos tanto en columnas como en filas, con control fino de anchos, altos, huecos y áreas. Es ideal para cuadrículas de tarjetas, páginas con cabecera / contenido / barra lateral / pie, y composiciones complejas.

Piensa en Grid como una rejilla invisible. Defines columnas y filas en el contenedor; luego “colocas” cada ítem en la celda (o área) que quieras. Para listas unidimensionales, Flexbox suele ser más simple; para tableros y páginas completas, Grid brilla.

7.4.1. Contenedor grid — propiedades clave

.grid {
  display: grid;                               /* activa Grid */
  grid-template-columns: 200px 1fr 1fr;        /* 3 columnas: fija + 2 fluidas */
  grid-template-rows: auto 1fr auto;           /* 3 filas: alto contenido */
  gap: 1rem;                                    /* huecos entre celdas (row + column) */
  /* justify-content / align-content: distribuyen la rejilla completa dentro del contenedor
     justify-items / align-items: alinean el contenido de cada celda por defecto */
}
  • grid-template-columns / rows: define la rejilla explícita (columnas/filas).
  • gap: separación entre celdas (mejor que márgenes sueltos).
  • repeat(), fr, minmax(): atajos y unidades muy potentes (debajo los vemos).
  • grid-auto-flow: controla cómo se colocan ítems que no especifican posición (row | column | dense).
  • justify-items / align-items: alineación por defecto dentro de cada celda (start, center, end, stretch).
  • justify-content / align-content: mueven el “bloque” de la rejilla cuando sobra espacio.

7.4.2. Ítems grid — colocación y alineación

.item-a {
  grid-column: 1 / 3;        /* ocupa de la col 1 a la 2 (sin incluir la 3) */
  grid-row: 1 / 2;           /* ocupa la primera fila */
  /* atajos:
     grid-column: span 2;    ocupa dos columnas desde su posición actual
     grid-area: fila-inicio / col-inicio / fila-fin / col-fin */
  justify-self: center;       /* alinea ESTE ítem horizontalmente dentro de su celda */
  align-self: end;            /* alinea ESTE ítem verticalmente dentro de su celda */
}
  • grid-column y grid-row: definen en qué columnas/filas se coloca un ítem (puedes usar span para abarcar varias).
  • grid-area (forma numérica): grid-area: filaStart / colStart / filaEnd / colEnd.
  • justify-self / align-self: alineación de un ítem concreto (sobrescribe justify-items/align-items del contenedor).

7.4.3. Unidades y funciones imprescindibles

  • fr: “fracciones” del espacio disponible. Ej.: grid-template-columns: 1fr 2fr; → la segunda columna ocupa el doble que la primera.
  • repeat(n, …): repite patrones. Ej.: repeat(3, 1fr) → tres columnas iguales.
  • minmax(min, max): límites fluidos. Ej.: minmax(220px, 1fr) → nunca menos de 220px, pero puede crecer.
  • auto-fill / auto-fit: rejillas responsivas que “llenan” el ancho con tantas columnas como quepan.
    • auto-fill: reserva huecos aunque no haya ítems (útil en ciertos patrones).
    • auto-fit: colapsa huecos vacíos → columnas se estiran para ocupar el espacio.
/* Rejilla fluida de tarjetas */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 1rem;
}

7.4.4. Áreas nombradas: maquetación “de tablero”

Nombrar áreas hace tu CSS muy legible y fácil de reordenar.

.layout {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
  gap: 1rem;
}
.header { grid-area: header; }
.aside  { grid-area: aside; }
.main   { grid-area: main; }
.footer { grid-area: footer; }
<div class="layout">
  <header class="header">Header</header>
  <aside  class="aside">Aside</aside>
  <main   class="main">Contenido principal</main>
  <footer class="footer">Footer</footer>
</div>

Cambiar el orden visual es tan fácil como modificar el mapa de grid-template-areas (sin tocar el HTML). En móvil puedes pasar a una sola columna con media queries.

7.4.5. Rejilla implícita vs explícita

  • Explícita: lo que declaras con grid-template-*.
  • Implícita: filas/columnas “que aparecen” cuando colocas ítems fuera de la rejilla explícita.
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* explícitas */
  grid-auto-rows: 180px;                 /* filas implícitas tendrán 180px */
  grid-auto-flow: row;                   /* cómo se rellena el “sobrante” */
}

7.4.6. Alineación en Grid (resumen rápido)

  • justify-items / align-items (contenedor): alineación por defecto de cada ítem dentro de su celda.
  • justify-self / align-self (ítem): alineación puntual de un ítem.
  • justify-content / align-content (contenedor): mueven el “bloque” de la rejilla cuando sobra espacio total.

7.4.7. Patrones típicos (con explicación)

a) Galería de tarjetas responsiva

Se adaptan las columnas según el ancho disponible, sin saltos bruscos.

.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 1rem;
}
b) “Holy Grail Layout” (header, nav lateral, main, footer)
.holy {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header"
    "nav    main"
    "footer footer";
  min-height: 100dvh;
}
.h-header { grid-area: header; }
.h-nav    { grid-area: nav; }
.h-main   { grid-area: main; }
.h-footer { grid-area: footer; }

/* En móvil: una columna */
@media (max-width: 768px){
  .holy {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "nav"
      "main"
      "footer";
  }
}
c) Hero superpuesto (overlap) con texto encima de imagen

Varias capas en la misma “celda” usando la misma área o mismas líneas.

.hero {
  display: grid;
}
.hero img {
  grid-area: 1 / 1;            /* misma celda */
  width: 100%; height: auto;
}
.hero .copy {
  grid-area: 1 / 1;
  align-self: end;              /* baja el texto */
  padding: 2rem;
  color: white;
  text-shadow: 0 2px 8px rgba(0,0,0,.5);
}
d) “Masonry” sencillo (alto variable) con auto-rows + span

No es un masonry real, pero imita el efecto asignando altura base y haciendo que los ítems “abarquen” filas según su contenido.

.masonry {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  grid-auto-rows: 8px;     /* unidad base (row-height) */
  gap: 12px;
}
.masonry > article {
  /* calculas cuántas “unidades” necesita el contenido */
  /* truco común: medir el contenido y ajustar con JS si hace falta;
     sin JS, define spans aproximados por clase */
}
.masonry .h2x { grid-row: span 24; }  /* 24 * 8px = 192px aprox. */
.masonry .h3x { grid-row: span 36; }  /* 288px aprox.            */

7.4.8. Líneas y nombres (para colocación precisa)

Puedes nombrar líneas para colocar ítems de forma expresiva.

.lines {
  display: grid;
  grid-template-columns:
    [izq] 1fr [centro] 2fr [der] 1fr;
}
.feature {
  grid-column: centro;  /* ocupa la columna central (entre las líneas nombradas) */
}

7.4.9. Errores comunes y cómo evitarlos

  • Confundir justify-* con align-*: el primero es horizontal en LTR, el segundo vertical (salvo que cambies writing-mode).
  • Olvidar min-width: 0 en ítems con contenido largo → pueden “reventar” la columna.
  • Mezclar width fijos con fr sin pensar → columnas que no se adaptan bien.
  • Usar order visual (con áreas) sin considerar lectura semántica → cuida la accesibilidad igual que en Flex.

7.4.10. Mini-reto práctico

  1. Construye una rejilla de tarjetas con auto-fit y minmax(240px, 1fr) que funcione desde móvil a escritorio sin media queries.
  2. Maqueta una página con grid-template-areas y cambia el orden de aside y main solo con CSS en pantallas estrechas.
  3. Crea un hero superpuesto y alinea el texto al centro en escritorio y al fondo en móvil solo con propiedades de alineación de Grid.

Cuándo usar Grid: plantillas de página, maquetas de marketing, galerías, paneles con áreas definidas en dos ejes. En componentes internos (botones, formularios), Flex suele ser más simple.

Checklist de decisión rápida:

  1. ¿Basta con el flujo normal? → display:block/inline.
  2. ¿Alineación en un eje? → Flex.
  3. ¿Filas y columnas? → Grid.
  4. ¿Elemento decorativo superpuesto/badge/menu fijo? → Position.

7.7. Mini-retos guiados

  1. Badge en tarjeta: añade una etiqueta “Oferta” en la esquina superior derecha usando position:absolute dentro de un contenedor con position:relative.
  2. Navbar responsive: con Flex, coloca logo a la izquierda, menú en el centro y CTA a la derecha; que el menú pase a columna en <640px.
  3. Landing sencilla con Grid-areas: header, aside, main, footer. En móvil, una sola columna; en escritorio, aside a la izquierda.

8. Variables CSS (custom properties)

Las custom properties (variables CSS) son valores nombrados que se definen en CSS y se pueden reutilizar en cualquier regla con var(). A diferencia de las variables de preprocesador (Sass/Less), las de CSS viven en el navegador: participan en la cascada, heredan y pueden cambiar dinámicamente (p. ej., con clases, media queries o JavaScript). 

/* 1) Definición global (documento) */
:root{
  --brand: #1F1769;
  --text:  #1f2937;
  --space-2: .5rem;
  --space-4: 1rem;
}

/* 2) Uso con var() */
h1{
  color: var(--brand);
  margin-block: var(--space-4);
}

/* 3) Ámbitos: redefinir en un contenedor concreto */
.card{
  --card-bg: #fff;
  background: var(--card-bg);
}
.card--warning{
  --card-bg: #fff3cd;               /* solo afecta dentro de .card--warning */
}
  • Dónde declarar: usa :root para “tokens” globales; redefine en componentes/variantes cuando lo necesites.
  • Herencia: las custom properties heredan por defecto; un hijo puede “ver” las variables del padre.
  • Fallbacks: var(--gap, 1rem) usa 1rem si --gap no está definido.

9. BEM (Block • Element • Modifier)

BEM es una metodología para nombrar clases CSS de forma que tu código sea más legible, mantenible y escalable. No es un framework ni una librería, es simplemente una convención de nombres.

9.1. Los tres pilares de BEM

BEM divide tu interfaz en tres tipos de elementos:

1. BLOQUE (Block) - El componente independiente

Definición: Un bloque es un componente autónomo que tiene sentido por sí mismo.

Pregunta clave: "¿Puedo usar este componente en otra parte del sitio sin que dependa de nada más?"

Sintaxis: .nombrebloque (solo el nombre, sin prefijos)

Ejemplos de bloques:

  • .card → Una tarjeta que puede ir en cualquier sitio
  • .navbar → Barra de navegación
  • .button → Un botón

2. ELEMENTO (Element) - Parte del bloque

Definición: Un elemento es una parte interna de un bloque que no tiene sentido fuera de él.

Pregunta clave: "¿Esta parte tiene sentido si la saco fuera del bloque?" Si la respuesta es NO → es un elemento.

Sintaxis: .bloque__elemento (dos guiones bajos)

Ejemplos:

  • .card__title → El título de la tarjeta (solo tiene sentido dentro de .card)
  • .card__image → La imagen de la tarjeta
  • .card__description → La descripción
  • .navbar__logo → El logo de la navbar
  • .navbar__menu → El menú de la navbar
  • .navbar__item → Un elemento del menú

⚠️ Regla importante: Los elementos NO se anidan en el nombre. Aunque el HTML esté anidado, el CSS no:

<!-- HTML anidado -->
  <div class="card">
    <div class="card__header">
      <h3 class="card__title">Título</h3>  <!-- ✅ BIEN -->
      <h3 class="card__header__title">Título</h3>  <!-- ❌ MAL (no anides) -->
    </div>
  </div>

Aunque .card__title esté dentro de .card__header en el HTML, en BEM sigue siendo .card__title (pertenece al bloque .card, no al elemento __header).

3. MODIFICADOR (Modifier) - Variante o estado

Definición: Un modificador cambia la apariencia, comportamiento o estado de un bloque o elemento.

Pregunta clave: "¿Esto es una versión diferente o un estado especial del componente?"

Sintaxis: .bloque--modificador o .bloque__elemento--modificador (dos guiones)

Ejemplos de modificadores:

  • .button--primary → Botón versión primaria (azul)
  • .button--large → Botón grande
  • .button--disabled → Botón desactivado
  • .card--featured → Tarjeta destacada
  • .card--compact → Tarjeta compacta
  • .navbar--sticky → Navbar pegada al scroll
  • .modal--fullscreen → Modal a pantalla completa
<!-- Base: Botón normal -->
  <button class="button">Normal</button>

  <!-- Variante: Botón primario -->
  <button class="button button--primary">Primario</button>

  <!-- Variante: Botón grande y primario (múltiples modificadores) -->
  <button class="button button--primary button--large">Grande primario</button>

⚠️ Regla importante: El modificador se usa junto a la clase base, no solo:

<!-- ❌ MAL - Solo el modificador -->
  <button class="button--primary">Botón</button>

  <!-- ✅ BIEN - Base + modificador -->
  <button class="button button--primary">Botón</button>

9.2. Ejemplo completo paso a paso

Vamos a crear una tarjeta de producto usando BEM desde cero:

Paso 1: Identificar el BLOQUE

<!-- El bloque principal es "product-card" -->
  <article class="product-card">
  </article>
/* CSS del bloque base */
  .product-card {
    border: 1px solid #e5e7eb;
    border-radius: 8px;

10. Media queries (diseño responsive)

El diseño responsive consiste en que la misma página se adapte de forma inteligente al espacio disponible (móvil, tableta, escritorio, pantallas grandes, etc.). La base técnica son las media queries, que permiten aplicar reglas CSS solo cuando se cumplen ciertas condiciones del entorno: anchura de la ventana, orientación, densidad de píxeles, si el usuario prefiere "modo oscuro", etc.

Filosofía "mobile-first": escribe primero los estilos base pensando en pantallas pequeñas. Después, añade mejoras con media queries de min-width a medida que el espacio crece. Así, el CSS es más sencillo, predecible y eficiente (los móviles descargan menos reglas).

10.1. Requisito clave en HTML: el meta viewport

Inclúyelo en el <head> para que el navegador use el ancho real del dispositivo:

<meta name="viewport" content="width=device-width, initial-scale=1">

El viewport es la "ventana" a través de la cual el navegador muestra una página web. En un ordenador de escritorio suele coincidir con la ventana del navegador, mientras que en dispositivos móviles se ajusta al ancho de la pantalla. Muchos móviles antiguos simulaban un viewport más ancho para mostrar páginas "de escritorio" reducidas, generando textos diminutos. Por eso es imprescindible declarar el meta viewport en el <head>: así indicamos al navegador que use el ancho real del dispositivo y que escale correctamente los contenidos.

10.2. Unidades flexibles: la base del diseño fluido

Antes de entrar en media queries, es fundamental entender que el diseño responsive se apoya en unidades relativas en lugar de píxeles fijos. Usar unidades flexibles permite que los elementos se adapten proporcionalmente al contexto, reduciendo la necesidad de múltiples media queries.

10.2.1. Comparativa: unidades absolutas vs relativas

Unidades absolutas (evitar en responsive):

  • px: píxeles fijos, no escalan con preferencias del usuario

Unidades relativas (preferir en responsive):

  • %: porcentaje del elemento padre
  • em: relativo al font-size del elemento padre
  • rem: relativo al font-size del elemento raíz (<html>)
  • vw: 1% del ancho del viewport
  • vh: 1% del alto del viewport
  • vmin: 1% de la dimensión más pequeña del viewport
  • vmax: 1% de la dimensión más grande del viewport
/* Diseño rígido con píxeles */
.container{
  width: 960px;
  padding: 20px;
  font-size: 16px;
}

/* Diseño fluido con unidades relativas */
.container{
  width: 90%;
  max-width: 75rem; /* ~1200px si 1rem=16px */
  padding: 1.25rem;
  font-size: 1rem;
}

10.2.2. Cuándo usar cada unidad

rem — Ideal para:

  • Tamaños de fuente (escalan con preferencias del usuario)
  • Espaciados consistentes (padding, margin, gap)
  • Breakpoints en media queries

em — Útil para:

  • Espaciados proporcionales al texto del componente
  • Dimensiones que deben escalar con la fuente local

% — Perfecto para:

  • Anchos de contenedores
  • Alturas en relación al padre

vw/vh — Casos específicos:

  • Secciones a pantalla completa (hero sections)
  • Tipografía fluida (con cuidado, mejor usar clamp())
/* Ejemplo práctico combinando unidades */
:root{
  font-size: 16px; /* Base para rem */
}

.hero{
  height: 100vh; /* Pantalla completa */
  padding: 2rem 5%; /* rem vertical, % horizontal */
}

.card{
  width: 100%;
  max-width: 25rem; /* Limita el ancho máximo */
  padding: 1.5rem;
  margin-bottom: 1rem;
}

h1{
  font-size: clamp(2rem, 4vw, 3.5rem); /* Fluida entre 2rem y 3.5rem */
  margin-bottom: 0.5em; /* Proporcional a su propio tamaño */
}

Ventaja clave: si el usuario aumenta el tamaño de fuente en su navegador, todo el diseño escala proporcionalmente.

10.3. Sintaxis esencial de una media query

Una media query es una regla condicional en CSS que permite aplicar estilos únicamente cuando se cumplen ciertas características del entorno de renderizado. Lo más habitual es controlar el ancho del viewport para adaptar el diseño a diferentes dispositivos, pero también podemos consultar la orientación de la pantalla, la densidad de píxeles o las preferencias de accesibilidad del usuario. 

/* Se aplica cuando el viewport es de al menos 768px */
@media (min-width: 768px){
  .sidebar{ display:block; }
}
  • min-width y max-width: las más usadas (anchos del viewport).
  • Se pueden combinar condiciones con and: @media (min-width:768px) and (orientation: landscape){ ... }
  • Usa unidades relativas (em/rem) para que los cortes escalen si cambia el tamaño raíz de la fuente. P. ej. 48em ≈ 768px si 1em=16px.

10.4. Elegir los "breakpoints"

Cuando diseñamos de forma responsive necesitamos decidir en qué puntos del ancho de pantalla vamos a cambiar el diseño: esos son los breakpoints. No existe una lista única o "correcta", ya que cada proyecto tiene necesidades distintas. Lo recomendable es dejar que el contenido "mande": define un breakpoint cuando un diseño empieza a romperse o a verse incómodo.

No hay "medidas mágicas". En vez de copiar tablas de dispositivos, decide los cortes cuando tu diseño lo necesite (el contenido pide más espacio o cambia de organización). Aun así, como referencia práctica: 

:root{
  /* Breakpoints de ejemplo en em (≈ px si 1em = 16px) */
  --bp-sm: 36em;   /* ~576px: móviles grandes */
  --bp-md: 48em;   /* ~768px: tablets vertical */
  --bp-lg: 64em;   /* ~1024px: escritorio compacto */
  --bp-xl: 80em;   /* ~1280px: escritorio ancho */
}

10.5. Mobile First vs Desktop First

Existen dos enfoques fundamentales para escribir CSS responsive. La elección afecta tanto a la estrategia de diseño como al rendimiento y mantenibilidad del código.

10.5.1. Mobile First (recomendado)

Estrategia: empieza por los estilos para móvil (pantalla pequeña) y añade complejidad con min-width según crece el espacio. 

/* Estilos base: móvil */
.nav{
  flex-direction: column;
}

/* Tablet y superior */
@media (min-width: 48em){
  .nav{
    flex-direction: row;
  }
}

/* Desktop */
@media (min-width: 64em){
  .nav{
    justify-content: space-between;
    padding: 1rem 2rem;
  }
}

Ventajas:

  • Prioriza la experiencia móvil (mayoría de usuarios)
  • Menor CSS inicial para móviles = mejor rendimiento
  • "Progressive enhancement": añades capacidades según hay espacio
  • Más fácil escalar hacia arriba que simplificar hacia abajo
  • Fuerza a diseñar lo esencial primero

10.5.2. Desktop First

Estrategia: estilos base para escritorio y reduces con max-width para pantallas pequeñas. 

/* Estilos base: desktop */
.nav{
  flex-direction: row;
  justify-content: space-between;
}

/* Tablet */
@media (max-width: 63.99em){
  .nav{
    padding: 0.75rem;
  }
}

/* Móvil */
@media (max-width: 47.99em){
  .nav{
    flex-direction: column;
  }
}

Desventajas:

  • Móviles cargan y procesan estilos de escritorio innecesarios
  • Requiere "degradar" el diseño en lugar de mejorarlo
  • Más complejo mantener la coherencia visual

Recomendación: salvo casos muy específicos, usa siempre Mobile First.

10.6. Patrón de trabajo (mobile-first + cascada)

La estrategia mobile-first es la más recomendada porque obliga a diseñar con lo esencial desde el principio y aprovechar la cascada: primero declaramos estilos base que sirven en pantallas pequeñas y luego añadimos mejoras progresivas con min-width para dispositivos más grandes.

  1. Estilos base (móvil)
  2. Mejora progresiva añadiendo reglas dentro de media queries de min-width ordenadas de menor a mayor
/* 1) Base móvil */
.card-list{ display:grid; gap: 1rem; grid-template-columns: 1fr; }

/* 2) Tablet: 2 columnas */
@media (min-width: 48em){
  .card-list{ grid-template-columns: repeat(2, 1fr); }
}

/* 3) Escritorio: 3 columnas */
@media (min-width: 64em){
  .card-list{ grid-template-columns: repeat(3, 1fr); }
}

Orden importa: al usar min-width, declara las media queries de menor a mayor. Así, la cascada actúa a tu favor y evitas sobreescrituras innecesarias.

10.7. Flexbox responsive: layouts unidimensionales adaptativos

Flexbox es ideal para layouts en una dimensión (fila o columna) que necesitan reorganizarse. La clave está en combinar flex-wrap, flex-direction y propiedades flex de los items con media queries estratégicas.

10.7.1. Patrón básico: wrap automático

/* Los items se reorganizan automáticamente */
.flex-container{
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}

.flex-item{
  flex: 1 1 280px;
  /* flex-grow: 1 (crece), flex-shrink: 1 (se encoge), flex-basis: 280px (base) */
}

Sin media queries, los items saltan de línea cuando no caben 280px. En móvil: 1 columna; en tablet: 2; en desktop: 3 o más.

10.7.2. Navegación responsive con Flex

<nav class="nav">
  <a href="#" class="nav__item">Inicio</a>
  <a href="#" class="nav__item">Productos</a>
  <a href="#" class="nav__item">Blog</a>
  <a href="#" class="nav__item">Contacto</a>
</nav>
/* Móvil: vertical */
.nav{
  display: flex;
  flex-direction: column;
  gap: 0.5rem;
}

.nav__item{
  padding: 0.75rem;
  text-align: center;
}

/* Tablet+: horizontal */
@media (min-width: 48em){
  .nav{
    flex-direction: row;
    justify-content: space-around;
  }

  .nav__item{
    flex: 1; /* Todos ocupan el mismo espacio */
  }
}

10.7.3. Layout principal + sidebar

/* Móvil: apilado */
.layout{
  display: flex;
  flex-direction: column;
  gap: 1.5rem;
}

/* Desktop: lado a lado */
@media (min-width: 64em){
  .layout{
    flex-direction: row;
  }

  .main{
    flex: 3; /* Ocupa 3 partes */
  }

  .sidebar{
    flex: 1; /* Ocupa 1 parte (proporción 3:1) */
  }
}

Cuándo usar Flexbox: navegaciones, barras de herramientas, listas de items que deben wrappear, cuando el tamaño del contenido es dinámico.

10.8. CSS Grid avanzado: técnicas responsive sin media queries

Mientras que Flexbox brilla en layouts unidimensionales, CSS Grid es la herramienta perfecta para diseños bidimensionales. Lo realmente potente es que, usando funciones como auto-fit, auto-fill y minmax(), podemos crear grids que se adaptan automáticamente sin necesidad de media queries.

10.8.1. auto-fit con minmax: el grid mágico

.grid{
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 1.5rem;
}

¿Qué hace esto?

  • repeat(): repite el patrón
  • auto-fit: crea tantas columnas como quepan
  • minmax(250px, 1fr): cada columna mínimo 250px, máximo 1fr (se reparte el espacio)

Resultado: en un contenedor de 320px → 1 columna; 768px → 2-3 columnas; 1200px → 4 columnas. Todo automático.

10.8.2. auto-fit vs auto-fill

/* auto-fit: colapsa columnas vacías */
.grid-fit{
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
}

/* auto-fill: mantiene columnas vacías */
.grid-fill{
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
}

Con auto-fit, si sobra espacio, las columnas llenas se expanden. Con auto-fill, se crean columnas vacías que no se ven pero afectan el tamaño de las demás.

Recomendación: usa auto-fit en la mayoría de casos.

10.8.3. Grid Template Areas responsive

Las grid areas permiten reorganizar completamente el layout cambiando solo la plantilla. 

<div class="dashboard">
  <header class="dash__header">Cabecera</header>
  <aside class="dash__sidebar">Menú</aside>
  <main class="dash__main">Contenido</main>
  <footer class="dash__footer">Pie</footer>
</div>
/* Móvil: todo apilado */
.dashboard{
  display: grid;
  gap: 1rem;
  grid-template-areas:
    "header"
    "main"
    "sidebar"
    "footer";
}

.dash__header{ grid-area: header; }
.dash__sidebar{ grid-area: sidebar; }
.dash__main{ grid-area: main; }
.dash__footer{ grid-area: footer; }

/* Tablet: sidebar a la izquierda */
@media (min-width: 48em){
  .dashboard{
    grid-template-columns: 200px 1fr;
    grid-template-areas:
      "header header"
      "sidebar main"
      "footer footer";
  }
}

/* Desktop: layout complejo */
@media (min-width: 64em){
  .dashboard{
    grid-template-columns: 220px 1fr;
    grid-template-rows: auto 1fr auto;
    grid-template-areas:
      "header header"
      "sidebar main"
      "sidebar footer";
  }
}

La sidebar ahora se extiende hasta el footer sin cambiar el HTML.

10.8.4. Items de diferentes tamaños

.masonry{
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  grid-auto-flow: dense; /* Rellena huecos */
  gap: 1rem;
}

.item--wide{
  grid-column: span 2; /* Ocupa 2 columnas */
}

.item--tall{
  grid-row: span 2; /* Ocupa 2 filas */
}

.item--big{
  grid-column: span 2;
  grid-row: span 2; /* Ocupa 2x2 */
}

Cuándo usar Grid: layouts de página completa, galerías, dashboards, cuando necesitas control bidimensional, componentes de tamaño variado.

10.9. Ejemplo paso a paso: cabecera responsive

Una de las formas más claras de entender el poder de las media queries es ver cómo evoluciona un mismo componente a través de distintos tamaños de pantalla. En este ejemplo, trabajaremos con una cabecera compuesta por un logotipo y un menú de navegación. La iremos transformando de columna a fila y, finalmente, ajustaremos márgenes y separaciones en escritorios más amplios.

Gracias a funciones como minmax() y auto-fit, a veces podemos lograrlo sin media queries, aunque en otros casos necesitaremos cortes definidos para controlar mejor la apariencia.

Muchas veces puedes evitar media queries usando minmax() + auto-fit. Si necesitas control fino de columnas/gap, combínalo con cortes.

/* Opción B: control granular */

10.11. Imágenes responsive

Las imágenes son uno de los elementos más problemáticos en diseño responsive si no se tratan correctamente. Una imagen demasiado grande ralentiza la carga en móviles; una imagen con dimensiones fijas rompe el layout. Existen varias técnicas para asegurar que las imágenes se adapten correctamente.

10.11.1. Regla CSS básica (imprescindible)

img{
  max-width: 100%;
  height: auto;
  display: block; /* Evita espacio inferior por inline */
}

Esto hace que cualquier imagen nunca sea más ancha que su contenedor y mantenga su proporción.

10.11.2. Elemento <picture>: diferentes imágenes según contexto

Permite servir imágenes distintas (más pequeñas, recortadas, con diferente orientación) según el tamaño de pantalla. 

<picture>
  <source media="(min-width: 64em)" srcset="hero-large.jpg">
  <source media="(min-width: 48em)" srcset="hero-medium.jpg">
  <img src="hero-small.jpg" alt="Banner principal">
</picture>

El navegador elige la primera <source> cuya media query coincida, o usa <img> como fallback.

10.11.3. Atributo srcset y sizes: resoluciones múltiples

Para servir la misma imagen en diferentes resoluciones (optimizando para retina, ahorrando datos en móvil): 

<img
  srcset="
    producto-400.jpg 400w,
    producto-800.jpg 800w,
    producto-1200.jpg 1200w
  "
  sizes="
    (max-width: 48em) 100vw,
    (max-width: 64em) 50vw,
    33vw
  "
  src="producto-800.jpg"
  alt="Producto destacado"
>
  • srcset declara las opciones disponibles con su ancho en w (width descriptor)
  • sizes le dice al navegador qué espacio ocupará la imagen según el viewport
  • El navegador elige automáticamente la mejor opción

10.11.4. Background images responsive

Para imágenes de fondo, usa media queries o image-set():

/* Con media queries */
.hero{
  background-image: url(hero-small.jpg);
  background-size: cover;
}

@media (min-width: 48em){
  .hero{
    background-image: url(hero-medium.jpg);
  }
}

@media (min-width: 64em){
  .hero{
    background-image: url(hero-large.jpg);
  }
}

/* Con image-set (moderno) */
.banner{
  background-image: image-set(
    url(banner-1x.jpg) 1x,
    url(banner-2x.jpg) 2x
  );
}

10.11.5. Mantener proporciones con aspect-ratio

.video-container{
  aspect-ratio: 16 / 9; /* Mantiene proporción 16:9 */
  width: 100%;
}

.video-container iframe{
  width: 100%;
  height: 100%;
}

Antes se usaba el "padding-bottom hack", ahora aspect-ratio lo hace trivial.

10.12. Tipografía responsive

No solo los layouts necesitan adaptarse al ancho de la pantalla: la tipografía también juega un papel clave. Un título demasiado grande puede ocupar varias líneas en móviles, mientras que un título demasiado pequeño se pierde en pantallas grandes. Tenemos dos opciones: usar media queries para cambiar escalonadamente los tamaños de fuente o emplear funciones como clamp() para crear tipografía fluida que se adapte de forma automática entre un mínimo y un máximo.

10.12.1. Tipografía fluida con clamp()

/* Fluida: min, ideal (con vw), max */
h1{
  font-size: clamp(2rem, 4vw + 1rem, 3.5rem);
  /* Mínimo 2rem, ideal 4vw+1rem, máximo 3.5rem */
}

h2{
  font-size: clamp(1.5rem, 3vw + 0.5rem, 2.5rem);
}

p{
  font-size: clamp(1rem, 1.5vw, 1.125rem);
}

Ventaja: escala suavemente sin saltos bruscos.

10.12.2. Tipografía escalonada con media queries

/* Base móvil */
h1{ font-size: 2rem; }
h2{ font-size: 1.5rem; }
p{ font-size: 1rem; }

/* Tablet */
@media (min-width: 48em){
  h1{ font-size: 2.5rem; }
  h2{ font-size: 1.75rem; }
  p{ font-size: 1.0625rem; }
}

/* Desktop */
@media (min-width: 64em){

10.14. Funciones CSS modernas para responsive

Las funciones matemáticas de CSS permiten crear diseños adaptativos sin media queries o complementarlas para mayor flexibilidad.

10.14.1. clamp(): valor entre mínimo y máximo

/* Sintaxis: clamp(mínimo, preferido, máximo) */

h1{
  font-size: clamp(2rem, 5vw, 4rem);
  /* Nunca menor a 2rem ni mayor a 4rem, idealmente 5vw */
}

.container{
  width: clamp(320px, 90%, 1200px);
  /* Mínimo 320px, máximo 1200px, ideal 90% */
  padding: clamp(1rem, 3vw, 3rem);
}

10.14.2. min() y max(): elegir entre opciones

/* min() elige el MENOR valor */
.container{
  width: min(90%, 1200px);
  /* Si 90% es menor que 1200px, usa 90%; si no, usa 1200px */
}

/* max() elige el MAYOR valor */
.hero{
  min-height: max(400px, 50vh);
  /* Al menos 400px o 50vh, lo que sea mayor */
}

10.14.3. Combinar funciones

.card{
  width: clamp(280px, calc(33.333% - 1rem), 400px);
  padding: clamp(1rem, 2vw + 0.5rem, 2rem);
  font-size: clamp(0.875rem, 1.5vw, 1.125rem);
}

10.15. Container queries (nota avanzada)

Una de las grandes novedades en CSS son las container queries, que permiten aplicar estilos en función del tamaño del contenedor padre y no del viewport. Esto resuelve un problema histórico: antes un componente solo podía adaptarse al ancho de toda la ventana, aunque se usara dentro de distintos contextos. Con las container queries, cada componente puede volverse realmente independiente y adaptativo.

Las container queries permiten adaptar un componente según el tamaño de su contenedor, no del viewport. Útiles para componentes reutilizables en layouts variables. 

/* 1) Marcar contenedor */
.card-grid{
  container-type: inline-size;
  container-name: card-container; /* Opcional pero recomendado */
}

/* 2) Consultar el contenedor */
@container (min-width: 540px){
  .card{
    display: grid;
    grid-template-columns: 180px 1fr;
    gap: 1rem;
  }
}

/* Con nombre específico */
@container card-container (min-width: 400px){
  .card__img{
    aspect-ratio: 16 / 9;
  }
}

Diferencia clave: una @media pregunta por el viewport global; una @container pregunta por el espacio del contenedor padre. Mismo componente puede tener distinta apariencia según dónde se use.

11. Transiciones y Animaciones (transform, transition, animation)

En la web, animar significa modificar propiedades visuales de un elemento a lo largo del tiempo, creando la ilusión de movimiento o cambio de estado. CSS nos permite hacerlo de dos formas principales: transiciones, que suavizan el paso entre un estado inicial y otro final, y animaciones, que permiten definir secuencias más complejas mediante fotogramas clave.

Idea clave: las animaciones no son un adorno gratuito, sino una forma de dar feedback visual al usuario, guiar su atención y aportar continuidad a los cambios en la interfaz.

Dos aspectos a tener en cuenta: transform (traslada, rota, escala, sesga) y opacity se pueden animar sin recalcular el layout, así que son la base de transiciones suaves y eficientes. Evita animar width, height, top, left salvo necesidad.

Terminología rápida:

  • Transición = interpolación automática “de A a B” al cambiar un estado (hover, clase, atributo, etc.).
  • Animación = secuencia de fotogramas clave (@keyframes) con más control (bucle, dirección, pausa).

11.1. Transform: mover, escalar y rotar sin tocar el layout

La propiedad transform permite aplicar funciones geométricas a un elemento sin modificar el espacio que ocupa en el documento. El navegador “pinta” el elemento en otra posición, con otro tamaño o rotación, pero el flujo de la página permanece intacto. Esto lo hace muy eficiente y por eso es la base de la mayoría de animaciones modernas.

Las funciones más comunes son:

  • translate(x, y): mueve el elemento en los ejes horizontal y vertical.
  • scale(x, y): cambia su tamaño (proporcional si se da un solo valor).
  • rotate(ángulo): rota el elemento alrededor de su centro o de un origen definido.
  • skew(x, y): sesga el elemento inclinando sus ejes.

El punto de referencia es transform-origin (por defecto, el centro del elemento), que podemos cambiar a cualquier esquina o coordenada.

Composición: puedes encadenar varias transformaciones en la misma regla:
transform: translateX(30px) scale(.9) rotate(10deg);
El orden es importante: rotar y luego trasladar no es lo mismo que trasladar y luego rotar.

11.2. Transitions: del “antes” al “después” con suavidad

Una transición es la forma más sencilla de crear movimiento en la web: en lugar de que una propiedad cambie bruscamente, el navegador interpola sus valores a lo largo de un intervalo de tiempo. El resultado es un efecto suave, que da continuidad visual y mejora la percepción de calidad de la interfaz.

Para que una transición se ejecute necesitamos siempre tres elementos:

  1. Estado inicial: cómo se representa el elemento por defecto.
  2. Trigger (disparador): la acción que provoca el cambio (un :hover, :focus, añadir una clase con JS, etc.).
  3. Estado final: los nuevos valores de la propiedad o propiedades que queremos cambiar.

Cuando ocurre el trigger, el navegador calcula el paso del estado inicial al final interpolando los valores a lo largo del tiempo definido en transition-duration, aplicando la curva indicada en transition-timing-function (aceleración, desaceleración, lineal…).

Sintaxis (shorthand y propiedades)

La propiedad transition es un shorthand que combina varias subpropiedades. Se pueden escribir de forma abreviada o detallada: 

.btn{
  /* Shorthand: propiedad, duración, curva, retardo */
  transition: background-color .25s ease,
              transform .25s ease-in-out .05s;

  /* Equivalente en propiedades “largas”: */
  transition-property: background-color, transform;
  transition-duration: .25s, .25s;
  transition-timing-function: ease, ease-in-out;
  transition-delay: 0s, .05s;
}
  • transition-property: qué propiedades queremos animar (ej. background-color, transform).
  • transition-duration: cuánto dura la interpolación (ej. 0.3s o 300ms).
  • transition-timing-function: la curva de tiempo (ej. linear, ease, ease-in, cubic-bezier(...)).
  • transition-delay: cuánto tiempo espera antes de empezar.

Pasa el ratón por los cuadros (o toca en móvil) para ver cómo cambian del estado inicial al final de forma gradual. Cada ejemplo resalta un tipo distinto de transición:

11.3. Animations: @keyframes y control fino

Cuando el “viaje” no puede resolverse con un simple antes/después, necesitamos definir fotogramas clave (@keyframes). Una animación describe cómo evoluciona un elemento en varios pasos intermedios, no solo al inicio y al final. Por ejemplo: un “latido” que se expande y contrae, un círculo que rota continuamente, o un bloque que cambia de color varias veces.

Una animación se compone de dos partes:

  1. La definición de keyframes, que describe cómo cambian las propiedades en el tiempo (from/to o porcentajes 0% → 100%).
  2. La aplicación de la animación al elemento, mediante propiedades animation-* que controlan su ejecución.

Propiedades más habituales

  • animation-name: nombre de los @keyframes a usar.
  • animation-duration: cuánto dura un ciclo de animación (ej. 2s).
  • animation-timing-function: curva de aceleración (ease, linear, ease-in-out, cubic-bezier…).
  • animation-delay: retardo antes de iniciar.
  • animation-iteration-count: veces que se repite (número o infinite).
  • animation-direction: sentido (normal, reverse, alternate).
  • animation-fill-mode: cómo se comporta antes y después (none, forwards, backwards, both).
  • animation-play-state: permite pausar o reanudar (running, paused).

Ejemplos prácticos

Una vez vistas las propiedades básicas de las animaciones, es muy ilustrativo observar una serie de patrones típicos con @keyframes. En esta galería de ejemplos encontrarás casos sencillos y habituales en interfaces modernas: un bloque que se desplaza de un lado a otro, un color que pulsa suavemente, una rotación continua y una animación combinada de salto con escala. Estos patrones funcionan como base para crear interacciones más ricas y permiten apreciar claramente las diferencias entre transiciones (de un estado a otro) y animaciones (secuencias con múltiples pasos).

11.4. Accesibilidad: reducir movimiento y respetar preferencias

No todas las personas perciben las animaciones de la misma forma. Para algunos usuarios, los movimientos rápidos, constantes o bruscos pueden resultar molestos o incluso producir mareos. Por eso, los navegadores y sistemas operativos permiten expresar la preferencia prefers-reduced-motion.

Como desarrolladores, tenemos la responsabilidad de respetar esa preferencia. Esto no significa eliminar toda la riqueza visual, sino ofrecer alternativas más sutiles: por ejemplo, en lugar de desplazar un panel con translateY, se puede usar una transición suave de opacidad. 

/* Ejemplo: desactivar animaciones si el usuario lo solicita */
@media (prefers-reduced-motion: reduce){
  .ex5, .ex6, .ex7, .ex8{
    animation: none !important;
  }
  .ex1, .ex2, .ex3, .ex4{
    transition-duration: 0s !important;
  }
}

Consejo: además de prefers-reduced-motion, recuerda dar siempre feedback alternativo. Si un elemento “latía” para llamar la atención, al desactivar animaciones asegúrate de marcarlo con un color o icono para que siga siendo perceptible.

A lo largo de los años se han consolidado ciertos patrones de animación que mejoran la experiencia de usuario, así como errores frecuentes que conviene evitar. Veamos los más relevantes:

Patrones recomendados

  • Microinteracciones: pequeños cambios que confirman una acción o llaman la atención sobre un estado. Ejemplos: un botón que se eleva al pasar el ratón, un icono de “like” que palpita, un campo de formulario que vibra ligeramente al fallar la validación.
  • Timing natural: las animaciones deben imitar la física. Usa ease-out para entradas (rápido al principio y frenando al final) y ease-in para salidas (lento al principio y acelerando al irse).
  • Duraciones breves: la mayoría de las transiciones deben durar entre 150ms y 400ms. Más largas pueden aburrir; más cortas pueden resultar imperceptibles.
  • Fill mode: si quieres que el estado final de la animación persista, usa animation-fill-mode: forwards (o both si hay retardo).
  • Variables de consistencia: guarda duraciones y curvas de aceleración en custom properties para mantener coherencia en toda la UI. 
:root{
    --dur-fast: .18s;
    --dur: .25s;
    --ease: cubic-bezier(.2,.8,.2,1);
  }

  .btn{
    transition: background-color var(--dur) var(--ease),
                transform var(--dur) var(--ease);
  }
  .btn:active{
    transform: scale(.97); /* micro feedback al hacer click */
  }

Errores comunes

  • Usar transition: all sin control: puede animar propiedades no deseadas (ej. bordes, sombras) y provocar efectos extraños. Es mejor especificar solo las propiedades necesarias.
  • Abusar de animaciones continuas: un elemento que nunca deja de moverse distrae y fatiga visualmente. Úsalas solo en contextos como “loading spinners” o notificaciones.
  • No ofrecer alternativas: confiar únicamente en el movimiento para transmitir información deja fuera a usuarios con prefers-reduced-motion o dificultades de percepción.
  • Curvas de tiempo poco naturales: evita linear para movimientos físicos: la realidad nunca se mueve en línea recta constante, siempre acelera o frena.

Recuerda: una animación no es un adorno gratuito. Debe tener un propósito claro: informar, guiar la atención, confirmar una acción o dar continuidad entre dos estados de la interfaz.

12. Bootstrap: framework CSS para prototipado rápido

Bootstrap es uno de los frameworks CSS más utilizados en el mundo del desarrollo web. Su objetivo es ofrecer un conjunto de estilos predefinidos, componentes y utilidades listas para usar que permiten construir interfaces de usuario de forma rápida y consistente. Fue creado originalmente en 2011 por desarrolladores de Twitter y desde entonces ha evolucionado hasta convertirse en un estándar de facto en muchos proyectos.

Idea clave: Bootstrap no es magia: se trata de un conjunto de CSS predefinido, un sistema de rejilla (grid), clases de utilidades y, opcionalmente, componentes JavaScript. Al aprender a usarlo, comprenderás cómo aplicar clases en tu HTML para obtener resultados inmediatos.

12.1. ¿Por qué usar Bootstrap?

  • Velocidad: permite prototipar interfaces en minutos, sin tener que escribir CSS desde cero.
  • Consistencia: aporta un estilo visual coherente en botones, formularios, tipografía, etc.
  • Responsive de serie: incluye un sistema de rejilla basado en Flexbox y breakpoints adaptados a dispositivos reales.
  • Comunidad y soporte: documentación oficial muy completa y miles de ejemplos disponibles.

12.2. Cómo incluir Bootstrap en tu proyecto

Existen dos formas principales de añadir Bootstrap:

  1. Desde CDN: la forma más rápida, ideal para pruebas y prototipos. Solo debes incluir el enlace en tu <head>:
<!-- CSS de Bootstrap -->
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.2/dist/css/bootstrap.min.css" rel="stylesheet">

<!-- JS de Bootstrap (opcional, para componentes interactivos como modal o carousel) -->
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.2/dist/js/bootstrap.bundle.min.js"></script>
  1. Instalación local: descargando los archivos o mediante npm/yarn si trabajas con un proyecto más avanzado.

12.3. Sistema de rejilla (Grid)

El sistema de rejilla de Bootstrap es uno de sus puntos más potentes. Está basado en Flexbox y divide el ancho de la página en 12 columnas. Podemos indicar cuántas columnas ocupa un elemento en cada breakpoint (col-*, col-sm-*, col-md-*, col-lg-*, etc.). 

<div class="container">
  <div class="row">
    <div class="col-sm-4 bg-light">Columna 1</div>
    <div class="col-sm-4 bg-secondary text-white">Columna 2</div>
    <div class="col-sm-4 bg-light">Columna 3</div>
  </div>
</div>

En este ejemplo, en pantallas pequeñas (sm ≥ 576px), cada div ocupará 4 de las 12 columnas, por lo que en total se muestran 3 columnas iguales. En pantallas más pequeñas (menos de 576px), las columnas se apilan automáticamente.

Truco: si no especificas el número de columnas, Bootstrap reparte el espacio de forma automática entre las que haya. Ejemplo: class="col" en tres elementos → cada uno ocupa 4/12.

12.4. Tipografía y utilidades

Bootstrap incluye estilos de tipografía y clases de utilidades que nos evitan escribir CSS. Ejemplo: alinear, añadir márgenes, colores de fondo, etc.

12.7. Ventajas y limitaciones

  • Ventaja: rapidez y estandarización en prototipos y proyectos con deadlines ajustados.
  • Ventaja: enorme documentación y ejemplos listos.
  • Limitación: si se abusa, todas las webs “se parecen entre sí” (estilo Bootstrap genérico).
  • Limitación: dependes de muchas clases en el HTML, lo que puede complicar el mantenimiento si no lo entiendes bien.

¡Importante!: Bootstrap es una herramienta muy útil para prototipar o para proyectos rápidos, pero no sustituye aprender CSS desde cero. Lo ideal es usarlo con criterio, adaptando y sobrescribiendo estilos cuando sea necesario.

13. Sass: preprocesador CSS

Sass (Syntactically Awesome Stylesheets) es un preprocesador de CSS, es decir, una capa intermedia que permite escribir código con características adicionales y luego lo compila a CSS estándar que entiende el navegador.

Con Sass podemos trabajar de forma más organizada y productiva, especialmente en proyectos grandes donde el CSS crece mucho. No sustituye a CSS: lo amplía durante la fase de desarrollo.

Idea clave: el navegador nunca lee Sass directamente. Tú escribes en archivos .scss o .sass y una herramienta (Node, Gulp, Webpack, Vite…) los convierte en un único .css.

13.1. Características principales

  • Variables: define colores, tipografías o tamaños una vez y reutilízalos en todo el proyecto.
  • Anidamiento: escribe selectores dentro de otros, siguiendo la jerarquía del HTML.
  • Mixins: fragmentos de código que puedes reutilizar con parámetros.
  • Funciones: operaciones matemáticas o de color (lighten, darken...).
  • Módulos: dividir tu CSS en varios ficheros e importarlos de forma limpia.

13.2. Ejemplo básico

// Definimos variables
$brand: #4f46e5;
$radius: 12px;

// Mixin reutilizable
@mixin flex-center {
  display:flex;
  justify-content:center;
  align-items:center;
}

.button {
  @include flex-center;
  padding:.6rem 1rem;
  border-radius: $radius;
  background: $brand;
  color:white;
  font-weight:600;
  &:hover {
    background: darken($brand, 10%);
  }
}

13.3. Compilación a CSS

El código anterior se compilaría a:

.button {
  display:flex;
  justify-content:center;
  align-items:center;
  padding:.6rem 1rem;
  border-radius: 12px;
  background:#4f46e5;
  color:white;
  font-weight:600;
}
.button:hover {
  background:#3f3ab7;
}

Consejo: aunque Sass es muy potente, no olvides que CSS moderno también ofrece variables (--var), funciones (clamp(), color-mix()), anidamiento (ya disponible en borrador) y un ecosistema más robusto que nunca. Usa Sass cuando realmente necesites escalabilidad y organización en proyectos grandes.

14. Recomendaciones de diseño web

Aprender CSS no es solo memorizar propiedades, sino aplicarlas con criterio para crear interfaces claras, accesibles y atractivas. A continuación tienes una serie de pautas de diseño que conviene tener siempre presentes al maquetar páginas web.

14.1. Tipografía

  • Usa tamaños relativos (rem, em) y clamp() para tipografía fluida.
  • Mantén una jerarquía clara: h1–h6 deben usarse en orden lógico, no solo por estética.
  • La longitud óptima de línea es de 60–75 caracteres para párrafos.
  • Altura de línea recomendada: entre 1.4 y 1.6 para mejorar la legibilidad.

14.2. Color

  • Garantiza contraste mínimo AA (ratio 4.5:1 entre texto y fondo).
  • Usa una paleta reducida de colores principales + neutrales.
  • Apóyate en herramientas como Adobe Color o Coolors para generar paletas armónicas.
  • Si transmites estados (éxito, error, aviso), no dependas solo del color: añade iconos o texto.

14.3. Espaciado y layout

  • Utiliza un sistema de espaciado coherente (ej. múltiplos de 4px o 8px).
  • No abuses de <br> o márgenes “a ojo”: planifica el ritmo vertical.
  • Aprovecha Grid para estructuras grandes y Flexbox para alineaciones internas.

14.4. Consistencia visual

  • Aplica las mismas esquinas redondeadas, sombras y radios en todos los componentes.
  • Define estilos de botones y enlaces globales y no los redefinas en cada página.
  • Mantén una escala tipográfica y de espaciado homogénea en todo el sitio.

14.5. Accesibilidad y usabilidad

  • Usa landmarks HTML5 (header, main, footer, nav, aside).
  • Proporciona estados de foco visibles (:focus-visible) en enlaces y botones.
  • Testea con teclado: toda la web debe ser navegable sin ratón.
  • Respeta prefers-reduced-motion y ofrece alternativas cuando desactiven animaciones.

14.6. Rendimiento

  • Optimiza imágenes (formatos modernos como WebP o AVIF, loading="lazy").
  • Minimiza CSS y elimina estilos no usados (purgeCSS o similares).
  • No abuses de sombras, gradientes complejos o animaciones continuas: consumen CPU/GPU.
